# macOS 应用菜单栏设计提案

状态：设计提案，未实施。日期：2026-09-04（America/Los_Angeles）。
修订：2026-09-05，补齐系统菜单与 App 内入口的对应关系和作用范围。
代码基线：`4a90933a99170c462a48bda36225b1e12001b439`；实机观察：CC Pocket v1.9.6。

## 目标与现状

把桌面端已有能力变成可浏览、可搜索、可用键盘操作的系统命令，减少用户猜测图标和记忆隐藏快捷键的成本。

- 实机系统菜单只有 **CC Pocket**：About、Services、Hide、Hide Others、Show All、Quit，没有应用自定义菜单，也没有 Settings。
- [Main.kt](../../mobile/composeApp/src/desktopMain/kotlin/dev/ccpocket/app/Main.kt) 已有新建会话、打开文件夹、快速打开、终端、后退/前进、侧栏、刷新、切换电脑、置顶跳转和设置快捷键；未挂载应用 `MenuBar`。
- [MenuBarExtra.kt](../../mobile/composeApp/src/desktopMain/kotlin/dev/ccpocket/app/desktop/MenuBarExtra.kt) 已提供右侧状态图标与浮层。本提案主要补左侧应用菜单，右侧继续服务于后台查看状态和回到工作。
- [SettingsModal.kt](../../mobile/composeApp/src/desktopMain/kotlin/dev/ccpocket/app/desktop/SettingsModal.kt) 的快捷键页只列七项；其页签是局部状态，尚无 About / Shortcuts 的外部直达入口。
- `Main.kt` 的设置快捷键受 `connected` 限制，`DesktopApp` 也仅在连接后挂载。需要同时解决入口可用与设置实际可显示。
- Mac 关闭主窗口目前会调用 `exitApplication()`；不能仅加上名为“关闭窗口”的菜单便宣称有独立关闭行为。

## 推荐结构

`  CC Pocket  文件  编辑  显示  会话  电脑  窗口  帮助`

采用系统菜单的字体、间距、选中态、快捷键对齐和禁用态。品牌表达继续由 App 内容承担。菜单顺序遵循 Apple HIG：App / File / Edit / View / 应用专属 / Window / Help。

菜单栏、窗口按钮、右键菜单与快捷键复用业务命令，并显式传入各自的目标和入口上下文。高频的新建、搜索、文件、终端按钮继续留在窗口内；菜单提供文字入口和功能发现，不要求用户离开当前工作区才能操作。

### 与 App 内部入口的关系

交集是有意保留的，但分工必须清楚：系统菜单提供稳定的文字命令入口，窗口内按钮支持就近操作和持续显示状态，右键菜单作用于被点击的对象，右上角状态浮层支持 App 在后台时查看进度与进入会话。

首版保留现有有效入口，不用“新增菜单”作为删除窗口内按钮的依据。菜单上线后的界面简化另行评估；当前不新增第二套设置页、会话操作面板或连接管理页。

| 能力 | 现有 App 内入口 | 系统菜单对应 | 首版处理 |
| --- | --- | --- | --- |
| 新建会话 | 侧栏新建、项目行“在此新建”及空态入口 | 文件 > 新建会话… | 保留。全局入口沿用现有默认目录规则；项目行入口显式带该项目目录，不能被统一命令丢掉 |
| 打开文件夹 | 侧栏与项目范围快速打开面板 | 文件 > 打开文件夹… | 保留并共用 `openFolderAction`；本机/远端判断、取消行为保持一致 |
| 搜索与跳转 | 顶部搜索、全部项目、已归档会话 | 显示 > 快速打开…；文件 > 全部项目… / 已归档会话… | 打开同一快速打开面板，仅查询范围不同，不新建第二套搜索 |
| 侧栏、导航历史 | 窗口控制区的侧栏开关和前进/后退 | 显示菜单 | 保留；菜单状态与按钮同步，快捷键提示一致 |
| 文件、Git | 当前主会话顶部按钮 | 显示 > 文件… / Git… | 保留，打开同一个面板；已有面板再次打开时聚焦，不叠加重复浮层 |
| 终端 | 会话顶部 `>_` 打开方式菜单 | 显示 > 显示/隐藏终端 | 保留。顶部入口还承担内嵌/外部终端选择；系统开关只控制内嵌终端，两者命名和职责不可混写 |
| 切换电脑、连接详情 | 侧栏电脑选择器、窗口连接状态点 | 电脑菜单 | 共用同一选择状态与连接详情；电脑名称、在线状态继续留在窗口内，不迁成只能从菜单读取的信息 |
| 重命名、置顶、归档 | 侧栏具体会话行与右键菜单 | 会话菜单 | 保留。右键操作被点中的会话，系统菜单操作明确选中的当前会话；业务规则相同，目标允许不同 |
| 停止回合 | 对应会话的输入区停止按钮 / Esc | 会话 > 停止当前回合 | 保留输入区按钮。菜单作用于明确选中的会话，不能把另一列的局部停止重定向到主会话 |
| 设置、关于、更新、快捷键 | 侧栏底部设置入口及设置内页签 | App / 帮助菜单中的直接入口 | 复用现有设置内容、偏好和更新状态；保留底部入口及更新提示，首版不另建偏好存储或设置窗口体系 |
| 帮助 | 侧栏帮助与客服、设置帮助页 | 帮助菜单 | 复用现有帮助目的地；同一窗口内不额外再加常驻帮助按钮 |
| 审批、答问、模型与权限选择、接力、消息回退/分叉 | 审批卡、输入区、会话快捷操作、具体消息右键 | 首版不新增对应全局动作 | 保留上下文入口；不能为了让系统菜单“齐全”把所有局部动作搬进去 |
| 隐藏、最小化、全屏、关闭与退出 | 窗口交通灯及窗口行为 | App / 文件 / 显示 / 窗口菜单 | 补齐原生行为；同名动作与窗口控制一致，关闭与退出分别实现 |

这里的“复用”包含执行、能力判断、执行中状态、成功后的状态同步和失败反馈，而不只是都调用同一个函数。例如：

- 当前侧栏只在满足条件的 **Claude 会话** 上提供重命名（`Sidebar.kt` 的 `canRename`）；系统菜单不能仅凭“已有会话”就对所有 Agent 启用重命名。
- 菜单重命名应打开明确的编辑入口并在该入口显示错误；不能把错误只留在已收起侧栏里的某一行。共享的是编辑规则与业务命令，呈现位置可以不同。
- “在此新建”携带被点击项目，“归档此会话”携带被点击会话；不能为了统一入口，全部改为读取全局 `selectedSessionId`。
- 菜单的“复制”跟随文本焦点，“复制工作目录”使用会话目标；两者不共用一个含糊的全局复制动作。

以上是开发前需要遵守的入口契约；原生菜单实现与窗口内控件是否真正共享能力判断，要通过交叉操作验收。

### CC Pocket

1. 关于 CC Pocket → 直达现有 About 页。
2. 设置… `⌘,` → 应用设置；无需连接。
3. 检查更新… → 调用现有更新检查并展示结果；不自动安装。
4. 服务、隐藏 CC Pocket `⌘H`、隐藏其他 `⌥⌘H`、全部显示 → 系统行为。
5. 退出 CC Pocket `⌘Q` → 退出桌面客户端。

About 后、服务前、Quit 前分组。系统已有菜单项通过原生 handler 接线，避免重复创建第二个 App 菜单。退出客户端不应顺带停止独立 daemon 或远端 Agent；客户端内嵌终端的退出后果须另外明确。

### 文件

| 菜单项 | 快捷键 | 行为 |
| --- | --- | --- |
| 新建会话… | `⌘N` | 打开现有新会话流程，允许确认电脑、目录、Agent |
| 打开文件夹… | `⌘O` | 复用 `openFolderAction`；本机用本地选择器，远端用远端目录浏览 |
| 全部项目… | — | 打开现有项目范围的快速打开面板 |
| 已归档会话… | — | 打开现有归档范围的快速打开面板 |
| 关闭窗口 | `⌘W` | 关闭/隐藏当前主窗口，保留 App；需要生命周期补齐后交付 |

不加入没有产品对应对象的“保存”“打印”。首版不新增“最近打开”缓存，可在后续直接复用已有历史模型。

### 编辑

撤销 `⌘Z`、重做 `⇧⌘Z`；剪切 `⌘X`、复制 `⌘C`、粘贴 `⌘V`；全选 `⌘A`。

只操作当前编辑焦点/选择范围：搜索框、会话输入框、重命名框和内嵌终端各自处理。不把“复制”解释成复制整段会话，也不把文本撤销解释成 Agent 回滚。图片粘贴保留现有附件能力。

第一版没有“在会话中查找 ⌘F”：当前 `⌘K` 是电脑/项目/会话的模糊跳转，不是正文搜索。正文查找应作为独立能力设计。

### 显示

| 菜单项 | 快捷键 | 行为 |
| --- | --- | --- |
| 快速打开… | `⌘K` | 现有跨电脑/项目/会话跳转 |
| 后退 / 前进 | `⌘[` / `⌘]` | 现有会话导航历史；到边界时禁用 |
| 显示/隐藏侧栏 | `⌘\` | 动态文字；未连接时也有效 |
| 显示/隐藏终端 | `⌘J` | 现有内嵌终端展开/收起；校验本机目录与终端上下文 |
| 文件… | — | 现有文件与改动浏览面板 |
| Git… | — | 现有 Git 面板 |
| 进入/退出全屏 | `⌃⌘F` | 系统全屏；跟随真实窗口状态更新文字 |

第一版不加缩放字号、布局预设等新功能。不要把所有图标都翻译成一级菜单。

### 会话

菜单顶端的不可操作文字显示作用对象：`当前会话：标题`。执行时使用稳定的电脑 ID + 会话 ID，不能只凭屏幕标题。

- 重命名… → 复用现有会话重命名能力及 Agent/目录能力限制；不支持时保留灰显。
- 置顶会话 / 取消置顶 → 同现有置顶模型。
- 复制工作目录 → 复制当前会话目录。
- 分隔线。
- 停止当前回合 → 仅当该会话有可停止工作且当前用户可控制时启用；建议新增 `⌘.`，保留输入框已有 Esc 行为。
- 分隔线。
- 归档会话 → 沿用现有能力与状态限制。第一版不新增快捷键，避免输入焦点误触。

首版不放直接批准、自动批准或全局权限模式切换。权限决策继续在带上下文的审批卡完成。回退/分叉需要具体消息位置，保留在消息右键菜单。P2P 评审中心当前已降低入口显著程度，不升为一级菜单。

### 电脑

- 切换电脑… `⌘0` → 复用切换器。
- 已配对电脑列表 → 当前项带勾，离线项在文字上说明；离线电脑仍可选择以查看连接/恢复入口。
- 分隔线。
- 添加电脑… → 现有配对界面，后续仍由用户完成配对。
- 刷新项目与会话 `⌘R` → 复用 `refresh()`，不是刷新网页，也不表示重启 daemon。
- 连接详情… → 打开当前电脑的现有连接浮层。

首版不加“重启 daemon”“重置配对”等恢复捷径。右上角状态浮层继续处理跨电脑注意力和运行概况，避免在主菜单复制完整任务队列。

### 窗口

最小化 `⌘M`、缩放、显示主窗口。仅一个主窗口时不提供“新建窗口”“合并窗口”。“缩放”与进入全屏是不同命令。

### 帮助

CC Pocket 帮助、键盘快捷键、反馈问题…；Help 菜单的系统命令搜索在原生接入后实机验证，不把普通自定义搜索框称为系统帮助搜索。

## 状态与交互约定

| 场景 | 规则 |
| --- | --- |
| 未配对 / 当前电脑断线 | 菜单结构稳定；本地设置、关于、帮助、窗口、侧栏、电脑管理可用；远端动作禁用 |
| 没有当前会话 / 会话加载失败 | 重命名、归档、停止、文件、Git、终端禁用；可切换电脑/项目 |
| 会话闲置 | 停止禁用；不能因为“连接成功”就启用全部命令 |
| 查看历史 / 旁观 / 已接力锁定 | 使用现有命令能力和权限限制；菜单不得绕过 UI 的只读状态 |
| 分屏 | 编辑命令跟随真实键盘焦点；会话命令跟随明确选中的主会话。侧列输入焦点与主会话不一致时，首版禁用停止/归档等变更动作，直至完成显式聚焦；不要隐式切换主会话或误作用另一列 |
| 审批 / 模态输入打开 | 保留模态边界；禁用会改变底层会话或上下文的命令，编辑命令只处理模态内焦点 |
| 打开菜单期间状态变化 | 执行前重验目标 ID、连接、运行状态和权限，防止点到已切换的会话 |
| 不可用项 | 保留位置并灰显；必要时用只读上下文行说明原因，不在不同状态反复隐藏菜单项 |
| 命名 | 需要进一步输入或选择才执行的动作使用省略号；普通开关、停止、复制不加省略号 |

`⌘1–9` 保留置顶跳转。菜单接入时修复快捷键修饰符匹配：现有多处分支只检查 `mod + key`，添加 Shift/Option 命令会被旧分支误捕获。命令注册需要精确匹配修饰符，并确保菜单 accelerator 与 Compose preview 不重复执行。

## 实现建议

1. 新建 `DesktopCommands.kt`，统一命令 ID、文字资源、shortcut、目标、enabled、checked/state 与 execute。这里是 UI 命令层，不扩展 wire 协议。
2. 新建 `MacApplicationMenu.kt`，挂在 `Main.kt` 的应用/窗口宿主，覆盖连接页。优先验证 Compose Desktop `MenuBar` + macOS 屏幕菜单桥接；原生 About / Preferences / Quit / Reopen 用 AWT Desktop/macOS handlers。具体桥接兼容性仍需在当前 Compose 1.7.3 与打包 JDK 上做验证。
3. 将设置打开目标提升为可传入的页签，并让本地设置在断线时也能渲染。账号、电脑远端信息仍按各自连接条件加载。
4. 编辑命令需要明确的焦点适配。Compose TextField 与 Swing/JediTerm 不会因为添加一个 JMenuItem 就自动共用编辑行为；复用各自编辑管线，避免全局模拟按键造成递归。
5. 最后补齐 macOS 关闭/退出：保留主窗口状态和 App；Dock 点击、Window > 显示主窗口、右上角状态入口都能恢复。即便用户关闭状态图标，也必须可恢复和退出。内嵌终端运行时，关闭仅隐藏窗口；退出对 PTY 的影响需明确并验证。
6. 现有页面按钮和快捷键逐步接同一个命令层。Windows/Linux 保持各自平台菜单和快捷键行为，不将 Mac 菜单样式绘制到窗口内容中。

首版建议把上述“已有能力接线 + 编辑焦点 + 关闭/退出”一并完成；命令面板扩展为完整动作检索、动态最近打开、正文查找和更多布局能力留作后续。

## 验收

- 在实际打包的 `.app` 上确认菜单出现在系统顶栏，未登录/断线也存在；About / Settings 不重复，Help 搜索能力如实验证。
- 一个菜单项和对应快捷键只触发一次；文本框/图片剪贴板/JediTerm 各有合理编辑行为。
- 交叉入口状态一致：窗口内置顶后菜单显示“取消置顶”；从菜单打开文件/Git 后复用同一面板；窗口内折叠终端后菜单更新；检查更新的各入口展示同一结果。
- 同类命令的目标正确：当前会话 A 与右键会话 B 分别重命名/归档时操作各自对象；项目 B 的“在此新建”不使用项目 A 的目录。
- 同一目标的能力限制和错误反馈一致：不支持重命名的 Agent 在菜单中不可执行；菜单发起的失败在可见入口反馈，不依赖隐藏的侧栏行。
- 本机/远端打开文件夹保持正确电脑，远端同名目录不会被当作本机终端工作目录。
- 双列分别运行时，停止/归档绝不影响非目标会话；模态及只读条件不能绕过。
- 菜单打开期间切换或结束会话，旧 action 不误发。
- `⌘W` 后 Dock 可恢复；关闭状态图标后仍可恢复；`⌘Q` 退出桌面客户端且不停止独立 daemon。
- 全屏进出、最小化、窗口恢复、中文/英文、浅色/深色及 VoiceOver 菜单名称可用。
- 运行对应命令状态/焦点/窗口生命周期测试与桌面编译。普通 Compose UI 测试不能单独证明原生菜单正确。

## 规范来源

- [Apple HIG — The menu bar](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar)：菜单顺序、保持项目可见但禁用、平台菜单行为、状态图标职责。正文通过 Apple 官方 documentation JSON 读取。
- [Apple — Building and customizing the menu bar](https://developer.apple.com/documentation/swiftui/building-and-customizing-the-menu-bar-with-swiftui)：系统菜单结构与上下文命令组织原则。实现依然采用本项目 Kotlin/Compose 技术栈。
- [Apple — Keyboards](https://developer.apple.com/design/human-interface-guidelines/keyboards)：标准快捷键及作用范围。
- [JetBrains — Compose Multiplatform Goes Alpha](https://blog.jetbrains.com/kotlin/2021/08/compose-multiplatform-goes-alpha/)：Compose 提供 Window / MenuBar / Tray API；仅用于确认 API 路线，不能据此声称本项目打包兼容性已验证。
