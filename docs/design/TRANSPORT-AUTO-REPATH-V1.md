# 客户端自动选路 v1：直连预算、资格预检与空闲回切

状态：第一部分（#403，第 3 节）与 daemon 前置检查（4.6）已实现并合入本地 main（2026-10-06）；第二部分 4.1–4.5、4.7、4.8（#404 的空闲回切）已实现并合入本地 main（2026-10-06，桌面默认开、手机默认关），其中第 5 节「4.2 切换」的真实 WebSocket 集成测试与 4.4 的 A-3 客户端测试未做，手机端默认关闭、真机项未验证。对应 #403 与 #404。实现状态以源码为准。

负责人 2026-10-05 的四个决定是本文的边界：只在空闲时切回直连；App 内局域网开关另见 #405；daemon 默认绑定仍是本机回环；这台 Mac 已单独开启局域网绑定。

## 1. 定位

本文是[直连与中继路径选择评估](TRANSPORT-PATH-SELECTION-EVALUATING.md)里唯一保留的缺陷项 A0，加上「时机受控的一次普通重连」。它不是该文的阶段 A1 或阶段 B：

- 不做并行候选竞速，不做流式输出中的迁移，不开第二条 relay socket，不做 P2P 或 Tailscale 发现，不做面向用户的网络路径设置页。
- 继承该文 4.2 的约束：同一配对身份同一时刻只有一个业务发送者；不增加第二个 relay socket；切换电脑、移除配对时先失效计时器再取消任务。
- 继承 #142 到 #146 与 #298 的教训：不在 `PeerPresence` 上升沿直接拆健康的 relay socket；旧连接的迟到事件不得影响后继连接。

## 2. 现状

| 事实 | 位置 | 后果 |
|---|---|---|
| 传输启动时先拨一次直连；失败写 60 秒冷却并在同一次尝试里回落 relay | `PocketRepository.launchTransport` | 正常 |
| 直连的 3 秒超时只覆盖握手与密钥确认，不覆盖建连 | `DirectE2EConnection.connect` | iOS 的建连只受系统默认约束，黑洞地址要等 12 秒看门狗 |
| 12 秒看门狗用取消的方式中止直连，不写冷却 | `startConnectWatchdog` | 下一次重试仍先拨直连，可构造出「始终连不上」的循环 |
| 一旦落到 relay，只要 relay 不断就不再尝试直连 | 同上 | 同机的桌面 App 在 daemon 重启后数小时经 relay 绕行 |
| 拨直连前不看当前网络 | 同上 | 手机在蜂窝或别的网络上也会去拨存下的内网地址，并发出明文 `LanHello`（含设备标识） |

## 3. 第一部分（#403）：有界的直连尝试与资格预检

这一部分是缺陷修复，三个平台无条件生效。

### 3.1 建立预算

- `DirectE2EConnection.connect` 增加一个总预算 `DIRECT_ESTABLISH_BUDGET_MS`（3 秒，构造参数可注入），覆盖建连、WebSocket 升级、`LanHello`、Noise 握手、密钥确认全程。
- 预算到期抛 `DirectUnreachableException`，不是取消异常。这样 `launchTransport` 现有的处理会写冷却并在同一次尝试里回落 relay。
- 实现提示：Darwin 引擎的 `client.webSocket(url) { … }` 不限制建连时长，要把拨号放进子任务，由预算计时器取消，并只把这一种取消翻译成不可达；原有的握手超时保留，先到者生效。调用方的取消仍然是取消。
- 防御：12 秒看门狗触发时如果直连尝试仍在途，先写冷却再取消。
- 回落原因按枚举区分：拒绝、预算到期、握手失败、密钥不符。建连被拒这一类沿用它一直使用的 `fallback_used` 诊断码，另外三类此前从不上报，各用新码。

### 3.2 资格预检

拨直连之前先判断「这个地址在当前网络上有没有可能是那台电脑」。判断是纯函数，输入地址、本机网络快照、是否同机客户端。

| 地址 | 可以拨的条件 | 否则 |
|---|---|---|
| 回环（127.0.0.0/8、`localhost`、`::1`） | 客户端与 daemon 同机（桌面 App） | 跳过 |
| 内网或链路本地 IPv4（10/8、172.16/12、192.168/16、169.254/16） | 本机有一块 Wi‑Fi 或有线网卡，其 IPv4 子网（按该网卡的前缀长度）包含这个地址 | 跳过；只有蜂窝网卡在线时单独记为「仅蜂窝」 |
| 其他（公网地址、主机名、非回环 IPv6） | 总是可以拨 | — |
| 网络快照取不到 | 照今天的行为拨 | — |

- 跳过不写冷却，也不把地址记为坏地址；网络变了下一次照常判断。
- 快照取不到时放行：预算已经把代价限制在 3 秒，明文 `LanHello` 的可关联性是评估里已接受的残余；反过来若一律拒绝，平台接口出错时直连就永久失效。
- 网络快照用 `expect`/`actual`：桌面与 Android 用 `java.net.NetworkInterface`；iOS 用 `getifaddrs`。网卡类型按名字归类：iOS 的 `en*` 归 Wi‑Fi，`pdp_ip*` 归蜂窝；Android 的 `wlan*` 归 Wi‑Fi、`eth*` 归有线、`rmnet*`／`ccmni*`／`pdp*` 归蜂窝；桌面上非回环、非隧道（`utun`、`tun`、`tap`、`tailscale`、`wg`、`docker`、`bridge`、`vmnet`）的网卡归有线。其余一律不参与判断。
- 预检用在两处：`launchTransport` 的直连尝试之前，以及第二部分的探测之前。
- 收益：在蜂窝或别的子网上不再向陌生主机发明文 `LanHello`。别的网络恰好复用同一个内网网段时仍会拨，这一点不变。

## 4. 第二部分（#404）：空闲时回到直连

### 4.1 什么时候评估

只在同时满足这些条件时才有意义：当前活动传输是 relay；这个绑定存有一个未被拉黑的直连地址；连接处于活动状态；不是演示模式；配对有效。

四类信号只是**请求一次评估**，评估本身串行执行，在途时的新请求合并：

| 信号 | 评估时刻 |
|---|---|
| `PeerPresence` 由离线变在线（daemon 重启或恢复） | 5 秒后。现有的 `onComputerBackOnline` 行为不变，评估排在它的探测窗口之后 |
| 回到前台且连接在 relay 上 | 2 秒后 |
| `DaemonInfo` 里的直连地址变了 | 1 秒后 |
| 定时器 | 在 relay 上每 60 秒起步，逐次翻倍到 15 分钟封顶；回到直连或更换绑定时复位 |

平台的网络变化回调本版不接，由回前台和定时器覆盖。

### 4.2 一次评估做什么

按顺序判断，任何一步不满足就结束本次评估并记下原因：

1. 冷却中（上一次直连尝试失败未满 60 秒）：结束。
2. 资格预检（3.2）不通过：结束。
3. **探测**：对地址的主机与端口做一次有界的 TCP 建连（1.5 秒），连上立即关闭，不写任何字节。失败：结束，不写冷却，定时器照常退避。
4. **不空闲**：结束，等下一次信号；另外在 15 秒后补查一次，最多补 4 次。
5. 距上一次计划内切换不满 60 秒：结束。
6. **计划内切换**：先保持 Ready 的外观（复用现有的重连横幅宽限 `startReconnectGrace(restart = true)`），再走普通重连 `launchTransport(reconnect = true, force = true)`。

普通重连本身已经具备需要的性质：先退休旧 socket 再拨号（#142）；直连优先且有 3.1 的预算；直连失败在同一次尝试里回落 relay 并写冷却；`restoreAfterReconnect` 带着 #147 的游标重挂当前会话。横幅宽限让成功的切换不出现「重连中」。

探测为什么不能省：没有它，每次评估都要先拆掉健康的 relay 连接才知道直连通不通，这正是 #145 的第一块多米诺骨牌。

### 4.3 「空闲」的定义

全部成立才算空闲，写成一个函数并逐项测试：

- 主聊天与桌面的所有分栏都没有流式输出。
- 没有等待确认的提示、排队的回合。
- 没有待处理的审批或提问。
- 没有正在打开或切换的会话，没有正在进行的新建任务。
- 没有在途的上传、图片压缩或文件传输。
- 语音不在录音、转写或校对中。
- 没有在途的历史翻页、文件查看或导出。
- 没有在途的项目置顶同步。

### 4.4 不允许发生的事

- 不在 `PeerPresence` 上升沿本身拆连接；上升沿只是请求评估。
- 不出现第二条 relay socket。直连尝试期间的推送登记可能走短拨号；随后回落 relay 时两者可能互踢，这是评估里记录过的既有隐患（A-3）。本版用探测把「探测通过却直连失败」压到很少，并补一条客户端测试覆盖「直连尝试中登记推送 → 直连失败 → relay 启动」；做不出稳定的测试就在实施报告里说明，不谎报覆盖。
- 计划内切换不丢任何在途内容：有在途内容就不算空闲。
- 更换电脑、移除配对、断开连接时，评估与定时器先失效。

### 4.5 状态放在哪里

新建一个小组件 `RepathController`（commonMain，时钟、探测、空闲判断、发起重连都以参数注入），由 `PocketRepository` 持有一个实例并在断开与切换电脑时复位。不要把计时器和计数器直接加成仓库字段。

TCP 探测用 `expect`/`actual`：桌面与 Android 用 `java.net.Socket` 带超时建连；iOS 用 POSIX 非阻塞 `connect` 加超时等待。不新增依赖。

### 4.6 daemon 前置检查（评估 B-1(i)）

局域网连接的出站队列在连接结束时用的是 `close()`。评估里推断：会话扇出对一个写协程已死的连接执行 `send` 时可能一直挂起，使回合结束不了。本版会增加局域网连接的开关次数，所以先验证：

- 写一条集成测试：连接的写协程退出后，向它扇出一帧必须在有限时间内返回。
- 如果会挂起，把收尾改成等价于 `cancel()` 的语义（挂起中和之后的发送都立即失败），并确认断开的 sink 仍按今天的方式被忽略。
- 评估 B-1 的第二点（回退分支与交接迁移旁观者留下的死 sink）不在本版范围，除非上面的测试把它暴露出来。

### 4.7 开关与默认值

| 部分 | 默认 |
|---|---|
| 第一部分（预算、预检） | 三个平台都生效，没有开关 |
| 第二部分，桌面 | 开 |
| 第二部分，手机 | 关。提供一个内部开关供负责人真机验证；验收通过后再改默认 |

手机默认关的原因：#403、#404 的验收都要求 iOS 真机在 Wi‑Fi 与蜂窝之间来回验证，实施时做不到。桌面的回环地址永远可拨且没有网络归属问题，风险最小，也正是 #404 记录的现象所在。

### 4.8 诊断

只记枚举，不记地址、设备或会话标识。新增一个事件，维度为触发来源（上表四类）与结果（切到直连、回落 relay、因忙推迟、探测失败、预检不通过、冷却中、刚切换过）。登记进 [EVENT-CATALOG](../observability/EVENT-CATALOG.md)，并通过现有的事件目录对齐测试。不新增 `ErrorPath`。

## 5. 验收

自动化：

| 项 | 验证 |
|---|---|
| 3.1 预算 | 本地监听后不应答的端口：直连在预算加容差内以不可达结束；仓库层：直连超时或被看门狗中止后写了冷却，下一次尝试走 relay；调用方取消仍是取消 |
| 3.2 预检 | 纯函数表格：回环与是否同机、同子网、不同子网、仅蜂窝、Wi‑Fi 加蜂窝、不同前缀长度、畸形地址、主机名、快照为空；iOS 测试里取快照不崩溃 |
| 4.1–4.2 控制器 | 可控时钟：四类信号各自触发评估；评估合并；定时器退避与复位；冷却、预检、探测失败、不空闲、刚切换过各自的结果；不空闲时的补查上限 |
| 4.2 切换 | 临时端口上的真实 WebSocket 集成测试：在 relay 上、空闲、直连可达，切到直连且当前会话被重挂；探测失败时 relay 连接不被触碰 |
| 4.3 空闲 | 每一项阻塞条件各一个用例 |
| 4.6 daemon | 写协程退出后的扇出在有限时间内返回 |
| 回归 | `ReconnectStormTest`、`ScopedOutbox` 相关用例、`SilenceWatchdogTest`、`SessionOpenTimeoutTest` 不变且通过；仓库字段清单与桌面分栏守卫测试通过 |

需要真机、本版不声称完成的：

- iOS 在蜂窝网络下存有内网地址时，relay 启动不晚于预算加调度容差。
- iOS 与 Android 在 Wi‑Fi 与蜂窝之间来回时的回切。
- 桌面 App 在 daemon 重启后回到回环直连。
- Android 的网络快照实现本机没有 SDK，无法编译，由 CI 覆盖。
