# Codex 模型目录缓存与更新实施方案

状态：已实施并合入本地 `main`（2026-10-06 提交，未推送），自动化验证通过；本机 daemon 尚未更新，真机验收未做，详见文末。实施基线为 `895cb352`，后续维护遵循 [AGENTS.md](../../AGENTS.md)。本次没有发版或安装设备。

目标是让手机和桌面端打开 Codex 模型选择器时立即显示已有列表，同时在后台发现新增、隐藏、移除和能力变更。列表更新不应替用户改变已选模型，也不能让内置旧型号长期覆盖上游目录。

## 用户需求与交付范围

用户遇到模型列表有时响应较慢，希望一段时间内复用已经同步的结果，有变化再更新；同时担心写死型号导致新版本发布后仍执行旧版本。

本次实施覆盖 Codex 的目录获取、App 缓存、刷新策略、内置兜底和相关验收。手机与桌面共用核心逻辑。Claude 的 `fable` 等别名语义需要保持，并通过回归验证确认没有受影响。

不扩展到所有 Agent 的目录框架重构，不改 relay，不新增云端目录服务，不自动升级 CLI，不自动迁移用户指定的模型。发版、上架和生产部署不属于本方案的开发交付。

## 实施前基线与问题

| 环节 | 已核对的行为 | 对实施的影响 |
| --- | --- | --- |
| Codex 目录来源 | `CodexModelService.fetch()` 读取 `$CODEX_HOME/models_cache.json` 和 `config.toml`，没有请求官方接口 | 不能把当前慢直接归因于官方接口；反复读文件也不等于刷新上游目录 |
| 列表拼接 | 当前结果为“配置模型 + 可见缓存模型 + 全部 `CODEX_MODEL_IDS`”，再去重 | 动态目录成功时仍会追加旧的内置型号，可能抵消上游的隐藏或移除 |
| 目录过滤 | 本地解析要求 `visibility == "list"`，并排除所有非空 `upgrade` 项 | `upgrade` 的含义需按当前协议校准，不能直接等同于不可用 |
| App 查询 | 选择器打开和会话打开都会调用 `fetchModels()`，该方法直接发请求 | 没有请求有效期和并发合并；重复打开会重复查询 |
| App 存储 | `agentModels` 是内存状态，离开绑定环境时清空，没有目录持久化 | App 重启后需要重新取得列表；新增磁盘缓存须保留环境隔离 |
| 刷新失败 | `ModelsList` 只有在报错且新列表为空时才沿用上一份列表 | Codex 失败时会返回非空内置列表，可能覆盖此前成功的完整列表 |
| 能力使用 | `modelCapabilities` 会参与 effort、service tier 的选择及默认设置校正 | 旧缓存不能未经当前环境确认就触发偏好修改或能力判定 |
| 实际执行 | `CodexBackend` 将选中的模型值写入 `thread/start`、恢复请求和 `turn/start`；线程建立后接收返回的模型 | 缓存目录和更改执行模型必须分开处理 |

当前没有端到端耗时证据证明具体瓶颈。实施时分别记录“打开到首批列表可见”“请求到 daemon 回包”“上游目录读取”的耗时；日志仅保留来源、耗时、条目数、是否变化和错误类别，不记录凭据或原始响应。

## 模型名称与版本约定

保存和传输时区分显示名称与执行标识。App-server 目录按当前 schema 使用执行字段 `model`；本地缓存使用 `slug`。不得通过显示名称拼接执行 ID，也不得把目录条目的 `id`、`model`、`displayName` 永久假定为同一个字段。

| 用户选择 | 需要保持的语义 |
| --- | --- |
| 明确版本 ID | 原样发送。新版本出现只更新可选列表，不自动替换当前会话或已保存默认值 |
| 家族别名 | 原样发送别名，由对应 CLI 或供应商解析具体版本 |
| 默认选项 | 保留空值语义，让 CLI 使用其配置和默认策略；不能用目录第一项替代，也不能宣传为“永远最新” |

现有 Fable 菜单属于 Claude 后端，发送 `fable`，没有写死 Fable 5.0。新版本能否被别名解析取决于安装的 CLI 和供应商。用户通过自定义输入指定完整 ID 时，应继续尊重该选择。

Codex 上游可能提供升级建议；它用于提示迁移，不表示已经完成迁移或旧型号不可调用。目录中的可见性、升级建议和账号实际调用权限是不同概念。运行时模型展示继续以 CLI 回传的信息为依据，不能由缓存目录推断。

## 目标行为

1. 有匹配环境的成功缓存时，打开选择器立即展示，不等待网络或新进程启动。
2. 目录需要检查时在后台进行。已有列表可继续浏览；刷新失败保留同一环境的成功结果，并结束刷新状态。
3. 首次无缓存时可显示明确标注的内置兜底，并触发一次后台获取。动态目录成功后以动态结果替换兜底。
4. 内容相同时仅更新检查时间和刷新状态，不重置滚动位置、当前选择或持久化偏好，不重复写入整份列表。
5. 新型号和能力变化在刷新成功后出现；被隐藏或移除的旧型号不被内置表重新加入。
6. 当前会话、用户保存的默认项或手动输入的模型不在目录中时，仍保留其值和可见说明。它不应被包装成“上游已验证可用”，也不应被静默替换。

“没有变化就不用再读”具体实现为：有效期内复用，过期后检查，有变化才替换。没有上游推送或条件查询证据时，不能做到永不检查却及时发现新模型。

## daemon 目录与刷新

### 目录来源

优先通过安装的 Codex 的公开 `model/list` 协议获取模型和能力，沿用 Codex 自身的认证与 provider 配置。保留本地文件读取作为快速来源与兼容回退。Pairlet 自有缓存写入独立位置，不改写 Codex 的 `models_cache.json`。

实施前用当前 CLI 的 `app-server generate-json-schema` 核对请求参数、分页、执行字段及能力字段，并做只读目录探针。一次完整成功结果必须完成所有分页；超时或中间页失败不能当成完整目录删除旧条目。

短生命周期 app-server 可以参考 `CodexQuotaService` 的 transport：握手后只读目录，设置超时，完成、取消或失败后都回收进程，不创建会话、不发推理请求、不干预正在执行的会话。二进制选择和配置应与真实 Codex 会话一致，包括已有的自定义 executable 设置。

官方说明 `model/list` 可能返回内置或缓存目录。因此接入 RPC 后必须验证它在当前 CLI 下的刷新行为；不能把“RPC 成功”写成“已从官方网络取到最新目录”。若没有公开的强制上游刷新能力，交付中明确这一边界，使用可验证的 CLI 目录同步，不自行抓取 `auth.json` 或调用未确认的私有接口。[官方目录来源说明](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

### 来源与时间

内部结果至少区分动态目录、本地文件、上次成功结果和内置兜底，并区分以下时间：

- 本次向 CLI 或本地来源检查完成的时间。
- 当前目录内容发生变化的时间。
- 上游数据的原始获取时间，如来源实际提供；未知时保持未知。

重新读一份旧文件不能延长其上游新鲜度。缓存文件的修改时间和大小可用于减少重复解析；内容版本应根据规范化后的语义字段生成，不包含检查时间、错误文案等易变字段。服务端返回的 ETag 只有在对应接口确认支持条件请求时才使用，不能仅凭本地文件里有 `etag` 就假定存在可用接口。

### 列表合并

- 成功动态目录不再无条件追加 `CODEX_MODEL_IDS`。内置列表仅用于没有可用目录时的兜底。
- 保持来源的排序或明确的 priority 顺序；去重使用执行 ID。
- 完整目录新增、删除、可见性变化、显示名称、排序、默认项、effort、service tier 和升级建议变化均算语义变化。
- `upgrade` 非空不直接过滤；按已验证的当前协议决定显示与升级提示。已有测试中排除该条目的断言需要同步修正。
- 配置模型、当前模型和用户自定义模型可作为独立的保留项展示，不用它们证明目录完整性或权限。
- 区分“成功但为空”“来源缺失”“解析失败”“部分响应”。明确的空目录不能被悄悄替换成一份声称有效的旧目录。
- 同一环境刷新失败时优先保留成功列表，不能用非空兜底覆盖它。其他环境的旧列表不属于可复用结果。

### 建议初始参数

以下为实现起点，集中定义并通过实测调整，不增加用户设置页。

| 参数 | 初始建议 | 行为 |
| --- | --- | --- |
| App 同环境查询复用 | 10 分钟 | 连续打开多个入口只产生一次必要请求；进行中的请求合并 |
| daemon 向 CLI 检查目录的间隔 | 6 小时 | 有请求或活动连接时按需后台检查，不要求手机后台常驻；这不是官方数据新鲜度保证 |
| 单次目录任务总超时 | 15 秒 | 覆盖握手与所有分页；超时结束任务并保留成功缓存 |
| 自动失败重试 | 最短 1 分钟，退避至 15 分钟 | 持续开关菜单不能触发进程风暴；手动刷新也合并进行中的任务 |

绑定建立后预取；账号、provider、配置上下文或 CLI 版本发生变化时提前重新检查。daemon 每次处理目录请求时可快速检查本地文件是否变化，不必等 6 小时才接收 Codex 已经写入的新目录。

## App 持久化与环境隔离

### 缓存边界

缓存键包含稳定的电脑绑定身份和 Agent，再关联 daemon 提供的目录作用域。目录作用域应覆盖当前 Codex 账号、provider、影响目录的配置或 profile；CLI 版本变化是失效触发条件。若目录随工作目录变化，也必须反映该上下文。

App 不掌握完整 Codex 账号配置，不应自行猜测账号标识。由 daemon 依据可用的正式接口或配置元数据提供不含凭据的作用域标记，不能以 token 本文生成或传输缓存键。仅用 relay 账号或 `AgentKind.CODEX` 不能隔离不同电脑上的 Codex 环境。

跨 App 重启恢复时，尚未确认当前作用域的缓存只能作为“上次列表”预览，不得直接注入用于能力判断的权威状态，也不得触发 `reconcileDefaultCapabilities`。本次绑定完成后立即进行一次环境确认；确认一致后才提升为当前目录，不一致则切换到新作用域的结果。

### 存储内容

持久化模型目录、必要能力、来源、作用域、内容版本和时间，不要把整个 `ModelsList` 当作长期缓存直接恢复。该消息还包含权限档位等其他能力，恢复旧消息可能把旧 daemon 的能力带入新连接。

优先复用现有跨平台存储设施，采用带 schema 版本的单份记录或原子替换，并限制条目数、字段长度和总大小。解析失败时丢弃该缓存并回到正常获取流程。不要为这一个列表引入新的数据库依赖。

解除配对、凭据撤销时删除对应缓存。切换电脑时只加载新绑定的缓存，取消或隔离旧绑定的刷新任务；fleet 主连接与 satellite 切换同样遵守该规则。迟到回包必须通过连接代次和目录作用域校验，不能覆盖新环境。

### 界面与失败恢复

手机的新建会话、会话内选择器、设置默认模型，以及桌面的对应入口都使用统一缓存与刷新入口。提供轻量的刷新操作；有旧列表时不展示阻断式 loading，也不让刷新打断点击或使菜单自动关闭。

仅在有用时提示“正在更新”“更新失败，显示上次列表”或“使用内置列表”。协议细节、ETag、本机路径等不进入正常产品文案。新加文本与图标同排时遵循 `tightCenter`。

模型执行返回不可用错误时使目录失效并刷新，同时保留错误和用户选择，提示重新选择。不要自动换模型重发用户任务，以免改变任务的模型或费用语义。

## 协议兼容

保留 `ModelsList.models: List<String>` 和旧字段含义，让旧客户端仍能获得可用的 ID 列表。若要传输作用域、来源、名称和刷新状态，使用可选且带默认值的新字段；未知来源值应可安全降级，避免新增严格枚举导致旧端解码失败。

建议先确定最小目录元数据结构，至少表达作用域、来源、内容版本、检查时间，以及可选的上游时间。显示名和升级信息按执行 ID 关联。若确实需要 `forceRefresh`，给 `FetchModels` 增加默认 `false` 的可选参数；不得发明未经验证的 Codex RPC 同名参数。

缓存即时回包与后台更新必须约定完整：若 daemon 先返回缓存，任务完成后需通知仍属于同一作用域的请求方，且刷新失败或内容未变也能结束刷新状态。也可采用其他等效实现，但不能后台更新成功后让当前打开的菜单永远等不到结果。

新 App 连接旧 daemon 时，把缺失来源和作用域的结果视为兼容模式，不假定已通过账号确认，不跨进程恢复为可信能力。旧 App 连接新 daemon 时保留原请求响应路径。序列化变更需要执行协议兼容审查并覆盖双向测试。

## 实施顺序

1. 核对最新源码及现有改动，补目录请求的可控计时；用只读探针验证当前 CLI 的 schema、分页、来源和刷新行为。保留结论，原始响应放忽略目录。
2. 修正 daemon 的动态目录与内置兜底合并，明确成功、空结果、失败、升级建议和旧列表保留规则。
3. 实现目录任务合并、后台检查、超时回收、来源与作用域信息；确需协议字段时同步落实兼容。
4. 实现 App 持久缓存及“预览”和“当前能力”的分离，接入所有手机、桌面入口和绑定生命周期。
5. 加入手动刷新、错误提示及不可用后的失效逻辑，完成以下自动化和可见验收。

尽量将缓存状态与刷新调度提取为可注入时钟、存储和 transport 的小组件，避免继续把逻辑堆入 `PocketRepository`。不为降低改动行数而复用不属于当前环境的能力。

## 验收标准

| 场景 | 必须达到的结果 |
| --- | --- |
| App 重启，有同电脑的缓存 | 首批列表不依赖网络；作用域未确认时只作预览；不会改掉 effort、service tier 或默认模型 |
| 模拟目录请求延迟或超时 | 已有列表始终可见，菜单可操作，刷新最终结束并提示失败；无永久 spinner |
| 有效期内反复打开不同入口 | 共用结果与进行中的任务，无重复并发探测 |
| 上游目录完全相同 | 正确结束刷新，更新检查状态，不重置滚动和选择，不重写完整目录 |
| 新模型或能力出现 | 无需升级 Pairlet 即出现在列表；同步实际 ID、名称及支持的能力 |
| 上游隐藏或删除内置旧型号 | 新结果不把它重新追加；明确保存或正在使用的该 ID 仍可被识别和说明 |
| 带升级建议的模型 | 不因 `upgrade` 非空就当作不可用；不自动换成建议目标 |
| 目录明确为空或分页失败 | 分别表现为空结果和获取失败；部分页面不覆盖完整成功结果 |
| 缓存文件缺失、损坏或读取中变化 | 不崩溃；不把失败伪装成完整目录；有成功结果时保留，必要时使用标注的兜底 |
| 切换电脑、Codex 账号或 provider | 旧列表不作为新环境的可信目录，旧能力不清理新偏好，迟到响应无法覆盖新状态 |
| 解除配对、撤销凭据、fleet 切换 | 正确清理或隔离缓存和刷新任务，无跨绑定污染 |
| 明确版本、家族别名和默认选项 | 分别保持指定 ID、别名和空值语义；目录更新不触发模型切换或任务重发 |
| 新旧 App 与 daemon 组合 | 消息双向可解码，旧端保留列表能力，新端诚实降级 |
| 目录后台进程 | 成功、超时、取消和解析失败后都无残留进程，不创建推理会话，不影响正在运行的 Codex 任务 |

自动化优先覆盖实际故障边界：时间推进、任务合并、失败降级、作用域切换竞态、偏好不被旧能力修改、目录删除和协议兼容。沿用并更新 `CodexModelServiceTest`、`DefaultModelTest`、`SessionCapabilitiesTest`、目录提示测试及协议序列化测试，避免只测试 getter 或实现细节。

## 实施结果与边界（2026-10-05）

### 实际行为

- App 按绑定身份保存最后一份已确认目录；重启立即展示预览。预览不参与当前会话能力判断，不修改已保存模型、effort 或 service tier。相同 scope 和 contentVersion 不重复写整份目录；检查时间在内存更新，磁盘记录保留上次内容写入时的检查时间。
- 同一绑定、连接代次和目标工作目录合并请求，成功答复复用 10 分钟。绑定公告包含 Codex 时预取；手动刷新绕过复用。请求带 `requestId`，两帧均校验；切目录、切绑定或超时后的旧回包被丢弃。
- 手机两处新建会话和桌面新建弹窗传入待创建会话的目录；桌面目录输入稳定 700 ms 后查询。打开会话直接查询目标目录，`SessionLive` 的目录变化也会撤销旧请求。项目 B 的目录可以供新建弹窗展示，但不能用于活动会话 A 的能力判断。
- daemon 按工作目录缓存，成功检查复用 6 小时。全局配置、项目及父目录配置、CLI 文件或 Codex 缓存文件变化时提前检查。检查前后环境变化会丢弃该次成功结果并允许重查；普通失败按 1–15 分钟退避。
- 目录检查沿用 Codex 启动器和认证：`initialize` → `account/read` → `config/read {cwd}` → 全部分页 `model/list`。检查设置 15 秒超时；取消、超时、解析失败和成功都回收子进程，不创建推理会话。`~/项目` 按 daemon 用户目录展开。
- 成功目录不追加 Pairlet 内置旧型号；明确空目录保留为空。配置中明确指定的型号可保留显示。隐藏型号仍可有能力行；升级建议只保存为信息，不自动换型号。显示名与执行 ID 分离，Claude `fable` 等别名和空值默认语义保持原样。
- 手机、桌面的会话选择器、新建会话和设置入口共用目录状态与刷新按钮。刷新失败保留同作用域旧结果并显示错误；30 秒内没有最终答复也结束等待并提示重试。模型不可用会刷新目录，保留原错误及用户选择，不自动重发任务。

### 来源与信任

| 来源 | 展示与能力处理 |
| --- | --- |
| `dynamic` | 同进程确认 ChatGPT 账号身份、成功读取配置且使用 OpenAI provider 的 CLI 目录；匹配本次请求后可作当前能力依据。仅无错误且 scope 非空的结果可校正持久偏好并保存 |
| `dynamic-unconfirmed` | 已取得 CLI 目录，但账号身份或有效 provider 不能确认；App 可用作本次连接的临时能力，不能修改持久偏好或保存为已确认目录。daemon 的执行设置归一化保守透传 |
| `cli-builtin` | 未登录 CLI 的目录；只作标注来源的展示，不作为账号调用权限的证明 |
| `file` | Codex 文件缓存；只作预览，不提升为当前已确认能力 |
| `last-good` | 刷新失败时的旧结果；App 仅在当前上下文和 scope 一致时保留此前可信能力，不能单凭来源名称提升信任 |
| `builtin` / 未知来源 | 明确标注的兜底或预览，不用于清除用户设置 |

同一 `CodexModelService` 注入目录路由和 Codex Backend。Backend 仅从对应目录中仍匹配环境指纹的已确认目录（或其可信 last-good）归一化执行设置；文件回退、未确认目录、未知目录和空值默认模型均不推断能力。

持久化复用跨平台 SecureStore，仅保存模型行、能力和目录元数据；限制 128 条和 98,304 个 JSON 字符。读取损坏、超限或 schema 不符的记录时删除它。解除配对与两条凭据撤销路径均删除对应记录。该缓存不保存权限预设或认证凭据。

### 协议兼容

新增字段均为尾部可选字段并带默认值：`FetchModels.forceRefresh`、请求与答复的 `requestId`、`ModelsList.catalog` 和模型展示/能力元数据。来源使用字符串，旧端跳过未知字段。

新 App 带 token 时，daemon 可先回 `refreshing=true` 预览，再回最终结果；没有 token 的旧 App 只收一帧，未确认来源的能力行会被去掉。新 App 接旧 daemon 时保留无 token、无 catalog 的兼容路径，不将其持久化为已确认账号目录。旧协议缺少请求关联和作用域，无法提供与新协议相同的迟到回包隔离保证。

### 只读探针结论

核对版本为 `codex-cli 0.155.1`，原始响应保留在忽略目录，不进入仓库。

| 项目 | 已验证结论 |
| --- | --- |
| schema | 参数为 `cursor?`、`includeHidden?`、`limit?`；结果为 `data`、`nextCursor`。执行字段使用 `model`，没有依赖本次样本中 `id == model` 的巧合 |
| 分页 | cursor 是不透明字符串；收齐全部分页才发布成功目录，中间页失败不会当作完整目录 |
| 本机耗时 | spawn 到 initialize 约 20–45 ms；进程内 `model/list` 约 0.2–2 ms。这些测量不能代表手机或桌面列表的端到端耗时 |
| 工作目录 | 实际 `config/read {cwd: 项目目录}` 成功返回配置对象及 provider/profile 字段，样本约 5.1 ms；进程退出已确认 |
| 未登录 | 空 `CODEX_HOME` 下 `model/list` 仍成功返回 CLI 内置目录，需要同进程账号信息区分；成功读取列表不证明账号有调用权限 |
| 上游刷新 | 短生命周期探针没有观察到改写 `models_cache.json`；其他持续运行的 app-server 曾改写该文件。公开 `model/list` 无强制联网刷新参数，不能承诺每次 RPC 都拿到官方最新目录 |

账号变化若尚未体现在 CLI 返回或本地缓存/配置元数据中，Pairlet 无法即时发现；下一次检查或手动刷新会重新核对。时间字段区分检查完成、目录内容变化和来源实际提供的上游时间。
