# Chat Rhythm v1 — 移动端会话详情排版整理

状态：原型已获用户确认并由 Opus 实现；实际规格差异与验证结果见 README。

## 问题与证据

用户提供的深色手机截图显示：消息来源、正文和复制各占独立区域；整条消息末尾的复制行制造零碎留白；执行过程的工具数、失败、无结果、展开文案拥挤；底部状态、输入框与多个胶囊堆叠。用户认为整屏杂乱，明确反对为了隐藏复制而增加菜单、二次选择或陌生手势。

原始截图包含个人机器名与会话内容，不上传；向 Claude Design 提供脱敏的结构描述及等量示例。

## 范围与基线

- 项目：cc-pocket Design System 2.0，`eb401868-d618-47f7-b8d4-4641117d566d`。
- 只新建 `Chat Rhythm v1.dc.html`，必要辅助文件以 `ChatRhythmV1` 开头；不覆盖旧文件。
- 基线：Chat Master v2、Chat Roles v1、Chat Quote v1、Tool Process Live v1；后两者当前实现差异以本 brief 为准。Core List Chat v1 仍是未实施提案。
- 手机会话详情，正文优先；头部、执行过程与输入区只调整视觉组织。桌面、审批、协议及运行逻辑不在本轮范围。
- 沿用项目设计系统、中性用户容器、Agent 无容器文档流、引用竖线与代码块，不改成左右窄气泡或卡片堆叠。

## 核心方向

1. 整条消息复制收进已有来源行，保留常驻的一键复制，去掉正文下单独占行的复制。
2. 引用与代码块保留各自的一键复制，范围必须清楚；不改为更多菜单、先选文字、轻点唤出、仅长按等隐藏入口。
3. 长按正文仍是文字选择；浏览器原型的选择不等于真机手势验证。
4. 统一对齐与消息间距，保持可读正文字号和足够点击区域，不靠降对比度、缩字或删正文制造清爽。
5. 复制成功反馈不改变布局；复制失败不得显示成功。复制当前收到的完整消息，不仅是屏幕可见部分。
6. 执行过程的失败与无结果分别可见，折叠/展开仍是一键；实时行在步骤切换中固定高度。
7. 底部减少重复边框与胶囊，保留运行/排队、输入、附件、模型、会话切换/未读、上下文、语音和停止/发送。头部已有信息区展开能力可以复用，模型不必在上下重复强调。

## 真实能力约束

已有消息文本、来源、代码、引用与附件；已有一键复制与局部选择。普通工具有名称、参数预览、完成/失败/无结果、并行与本机观察到的计时。运行过程第一步即创建容器；无工具运行时保留最近步骤与结果，下一步到来再更新。没有真实进度百分比、ETA、自动重试或故障原因推断数据。回合结束后的无结果不得伪装为仍在运行。原型内切换场景、主题和字号是画板控件，不是产品新功能。

## 交付与验收

- 一个推荐方向的高保真可交互原型，中文、深色优先，附浅色。
- 同样文案和字号的现状/整理后对比；一屏呈现上轮结尾、用户短消息、Agent 回复、带失败与无结果的执行块、完整头部与底部。
- 支持复制整条/引用/代码及成功反馈、执行过程展开/收起、对话滚动、头部信息展开。
- 覆盖长回复与引用/代码、运行/已结束、小屏 320pt × 1.6 字号；常规主稿 402×874。
- 简短规格说明：尺寸、间距、颜色、操作与复制范围、长消息的入口取舍、未验证事项。
- 使用合成示例，保留真实信息密度，不虚构线上执行结果。
