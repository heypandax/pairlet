# Voice Memo to Tasks v3.1 — 整理可选与整理 Agent · UI 设计 brief

版本：2026-09-30（UTC+8）。来源：用户决定整理步骤适配 Codex、接口可插拔，并且电脑上没有整理 Agent 时转写照常可用。本文只改与“整理”相关的几处，其余页面沿用 v2.1 / v3。

## 产品语义的变化

- 转写不再依赖任何 Agent。电脑上只要有本地转写就能录音、转写并进入结果页。
- “整理”（把转写拆成标题、摘要、待办）由电脑上可用的整理 Agent 完成，目前是 Claude 和 Codex，以后会加其他。优先用 App 设置里的默认 Agent，默认 Agent 没有适配时用电脑上其他可用的，都没有时不整理。
- 没有整理时，结果页以转写原文为主，待办由用户手动拆，或把整段转写作为一项待办发出。之后电脑上有了整理 Agent，可以在结果页点“整理”补做。
- 整理仍然只整理、不执行：无工具、无 MCP、不读项目文件、不保存会话。用户看到的是哪个 Agent 整理的。

## 文件边界

在 cc-pocket Design System 2.0 项目内，只修改 Voice Memo to Tasks v2.dc.html 和 VoiceMemoV2Phone.dc.html。不新建文件，不修改其他文件，不读取 v1 文件。

## 需要设计的内容

### 1. 设置页“准备情况”的整理一行

三种情况：

- “整理 · Codex · 使用电脑配置”（示例默认 Agent 为 Codex）；
- 默认 Agent 没有适配、改用其他可用 Agent：“整理 · Claude · 使用电脑配置”，附一行小字“默认 Agent Codex 暂无整理适配，改用 Claude”；
- 没有可用整理 Agent：“整理 · 不可用 · 只转写”，附一行“待办需要手动拆分；电脑上装好 Claude 或 Codex 后可以自动整理”。

没有整理 Agent 不再阻止“新建备忘”。首次说明的三条数据去向改为：“录音加密传到电脑本地转写”“有整理 Agent 时，转写文本交给它整理，可能发往其模型服务”“任务由你确认后派发”。

### 2. 处理页的第三阶段

- 有整理 Agent：阶段文字“整理待办”，说明“Codex · 使用电脑配置 · 不调用工具”（Agent 名按实际）。
- 没有整理 Agent：阶段文字“整理待办”，状态“跳过 · 没有整理 Agent”，说明“转写完成后直接进入结果页”。
- 整理 Agent 在处理途中变得不可用：与上面相同，状态“跳过 · Codex 已不可用”。

### 3. 结果页的“未整理”状态

转写完成但没有整理时：

- 顶部一条说明块：“未整理。可以手动拆分待办，或把整段转写作为一项发出。”有可用整理 Agent 时（例如电脑后来装好了）说明块里有按钮“用 Codex 整理”；点击后进入处理页只跑整理阶段。
- 转写原文默认展开，可读、可选择。
- 待办区为空，下方三个操作：“添加一项”“整段作为一项”“用 Codex 整理”（不可用时不显示第三个）。“整段作为一项”把转写原文填进一条新待办；转写超过单条待办长度上限时该按钮禁用并说明“转写太长，请手动拆分”。
- 标题为空时用转写的第一句。
- 已整理的备忘在摘要标签旁注明“Codex 整理”（Agent 名按实际）。

“未能整理成待办”（整理失败）仍是另一种状态，保留 v2.1 的呈现，只把按钮改为“用 Codex 重新整理”。

### 4. 确认派发

整段转写作为一项发送时，确认页该项前加一句小字“整段转写，目标会话的 Agent 会自行整理”。其余不变。

## 内容样例

电脑“我的 Mac”，默认 Agent 为 Codex；示例转写沿用 v2.1 的 142 字口述。

## 原型操作

原型必须能实际完成：

1. 设置页三种整理状态切换（演示控制放在手机框外）。
2. 没有整理 Agent：新建 → 录音 → 处理页第三阶段“跳过” → 结果页“未整理” → “整段作为一项” → 选目标 → 确认页显示小字说明 → 派发。
3. 未整理的结果页 → “用 Codex 整理” → 处理页只跑整理阶段 → 结果页出现待办，摘要旁注明“Codex 整理”。
4. 有整理 Agent 的正常路径不变，只是文字按实际 Agent。

## 视觉与验收

390 × 844 为主，补 320 宽和 200% 字号；触区不小于 48 dp；同行文本与图标、徽章视觉中心一致。画板增加一节“整理可选”，包含设置页三态、处理页跳过、结果页未整理、确认页小字，各一帧，以及 320 / 200% proof。完成后实际打开画板自查，输出改动摘要、已检查项、未验证项。
