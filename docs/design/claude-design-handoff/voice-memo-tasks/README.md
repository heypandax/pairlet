### Compose 实现备注

- 同行文本与形状、徽章、不同字号文本全部使用 `tightCenter`，`trim` 保持 `Trim.None`。
- 底部操作栏使用 `imePadding()` 和 `navigationBarsPadding()`，内容区独立滚动。
- 待办输入不限制行数，随内容增长；标题在大字号下换行。
- 汇总条文案由计数拼接，不引入新状态。

## 与冻结规格的差异及实现取舍

设计稿与 [总体方案](../../VOICE-MEMO-TO-TASK.md)、[代码设计](../../VOICE-MEMO-CODE-DESIGN.md) 不一致时，以后两者为准。

1. 样例文字写“Pairlet 桌面端 2.0.3 / 2.1.0”“在电脑上打开 Pairlet 桌面端”。电脑端是 daemon，能力由 `voiceMemoVersion` / `voiceMemoStatus` 判定，实现时文案改为“电脑端”，不显示虚构版本号。
2. 样例文字写“等待 30 秒后超时”。实际期限为转写 180 秒、整理 90 秒，界面只显示错误码对应的说明。
3. 录音页“放弃”在原型里直接丢弃。实现时保留这一行为；返回键仍走三选项。
4. “复制为新待办”在原型里默认勾选新项。来源是待核对项时，实现默认不勾选，由用户自己勾选后再派发。
5. 320 宽 200% 字号的确认页，正文可滚动区只剩约一行高。实现时正文与目标块一起滚动，提示和主按钮固定在底部。
6. 处理耗时为原型样例。实现显示实测值，缺测显示“未完整测得”。

设计要点：

- 第一级：“最近会话”（最多 5 行，点一下直接选中）和“项目”（最近使用的在前，显示会话数量与运行标记）。
- 第二级：标题为项目名；第一行固定为“在这个项目新建会话”，展开后选择 Agent，权限模式只读显示；其后是该项目的会话，不可选的写明原因。

- 新建时状态条显示“正在新建会话…”。新建失败时不发送任何消息，待办保持草稿，不自动重试。
- 会话建好后，备忘的目标改为这个会话，剩余项再次派发时发到同一会话。

与实现的差异：

- 原型的失败说明写了“等待 20 秒后超时”。实现只按原因词给说明，不写秒数。
- 原型里“正在新建会话…”出现在聊天页。实现中会话建好之前聊天页还不存在，这条提示先显示在备忘结果页顶部，会话打开后由聊天页的状态条接续。
- 原型假设新会话的名字取第一条消息的首句。实现中手机上显示的名字取第一条待办的前 48 个字符；电脑端会话列表里的标题由电脑端按自己的规则生成，首条消息带固定前缀，标题可能以前缀开头。
- 已有会话的权限模式：电脑端的会话列表不带模式。实现显示的是“这次打开会使用的模式”，即设置里的默认模式；目标恰好是正打开的聊天时用它当前的模式。

与实现的差异：

- 原型在没有整理 Agent 时录音页仍写“结束并整理”、2:45 提示仍写“开始整理”（brief 未要求改）。实现改为“结束并转写 / 开始转写”。
- 原型把“整段作为一项”的上限写成 600 字。实现按协议的单条待办上限（1,000 个码点）判断。
- 原型的整理 Agent 三态由演示控制切换。实现由电脑公告的适配器列表和 App 的默认 Agent 决定：默认 Agent 有适配时用它，否则电脑列出的第一个，都没有时只转写。
- 原型的自查把 App 默认 Agent 改成了 Codex 以配合样例；实现不改默认 Agent。
- 实现里任何待办发出之后不再提供“用 X 整理 / 重新整理”（重新整理会把已送达的项目重新变成草稿，有重复执行的风险）；原型没有这条限制。
- 电脑离线或版本过旧时，设置页整理一行写“暂时无法检查”，与转写一行一致；原型只画了三态。
- 列表行对未整理的备忘写“没有待办”，原型写“未整理 · 原文已保存”；`MemoHeader` 尚无该标记，后续补。
- “未能整理成待办”的正文泛称“整理 Agent”，不写失败的 Agent 名字（文档不记录失败的整理者）。

## 实现映射

| 设计稿 | 代码 |
|---|---|
| 列表、首次说明、删除确认、toast | `mobile/.../app/ui/memo/VoiceMemoScreen.kt` |
| 录音及其异常态 | `MemoRecordingPage.kt` |
| 处理三阶段及各异常态 | `MemoProcessingPage.kt`，文案与按钮表在 `MemoCopy.kt` |
| 结果编辑、确认派发 | `MemoDetailPage.kt` |
| 目标选择 | `MemoTargetPicker.kt` |
| 聊天状态条、气泡送达标记 | `MemoDispatchNotice.kt`，接入点在 `ui/App.kt` |
| 实验开关与准备情况 | `MemoExperimentalSection.kt`，接入点在 `ui/Settings.kt` 通用页 |
| 字号、状态形状、按钮 | `MemoKit.kt` |

实现与设计稿的其他不同之处：

- 颜色使用应用现有的 `Tok`，没有新增色值；浅色下 surface 为现有 token 的纯白。
- 主按钮复用现有的 `EntryPrimaryButton`，圆角 14、字号 15。
- 目标选择为整页，不是底部表单。
- 表单入场和状态切换动效没有实现；脉冲与 spinner 在系统要求减少动效时静止。
- 运行中的阶段显示“进行中”，不显示该阶段的分段用时；顶部显示总的已用时间。
- 草稿行始终显示“草稿”标记。
- 已归档、权限不足、需接管终端的会话不会预先出现在目标列表里标为不可选；进入目标时校验，不符合则不发送并返回备忘。

## 未验证

- 真实麦克风、加密上传、Whisper、Claude 均未接入原型；音量条和耗时是模拟值。
- 软键盘弹出、退后台暂停只有文字说明，原型没有模拟。
- 真机字体渲染、屏幕阅读器朗读顺序没有测试。
- 线上画板没有在可见窗口中逐帧目视检查；静态帧的核对依据是本地加载的同一份源码。
- v3.1：真实 Codex 整理的耗时和输出质量只在 daemon 之外探测过两次（约 32 秒），原型里的“整理 4.7 秒”是样例。
