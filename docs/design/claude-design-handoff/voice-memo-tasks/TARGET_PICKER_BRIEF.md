# Voice Memo to Tasks v3 — 目标选择与新建会话 · UI 设计 brief

版本：2026-09-30（UTC+8）。来源：用户在真机上试用 v2.1 实现后的反馈。本文只改“目标会话与确认”这一块，其余页面沿用 [v2.1](README.md)。

## 为什么要改

v2.1 的目标选择是一张平铺的会话列表。真机试用发现两个问题：

1. 会话多了以后，一张列表找不到想要的会话，也看不出它属于哪个项目。
2. 有些待办不属于任何已有会话，用户想在某个项目里新开一个会话来处理。v2.1 只能发到已有会话。

## 本轮范围与文件边界

在 cc-pocket Design System 2.0 项目内，修改 Voice Memo to Tasks v2.dc.html 和 VoiceMemoV2Phone.dc.html，把目标选择改为两级，并加入“新建会话”。不新建文件，不修改其他文件，不读取 Voice Memo to Tasks v1.dc.html 和 VoiceMemoDevice.dc.html。

新建会话时选择 Agent 的方式沿用项目里 Fast Start / New Task 已有的写法，不另造。

没有提到的页面和规则全部保持 v2.1：五种待办状态、逐条发送、多项提示原文、待核对不重发、确认按钮是唯一的执行授权。

## 需要设计的内容

### 1. 第一级：选项目

- 顶部“最近会话”：电脑上正在运行的会话，以及这台手机最近打开过的会话，最多 5 行。每行显示会话名、项目、Agent、状态。点一下直接选中，不必进入项目。没有可显示的会话时整段不出现。
- 下方“项目”：绑定电脑上的项目，最近使用的在前。每行显示项目名、会话数量或“暂无会话”，项目里有会话正在运行时带运行标记。点击进入第二级。
- 项目很多时可以滚动；本轮不做搜索、分组和置顶。
- 只显示当前绑定电脑上的项目。页面说明“只显示我的 Mac 上的项目”。
- 列表还在从电脑读取时显示读取中；读取失败显示原因和“重试”，不显示成空列表。

### 2. 第二级：选会话或新建

- 标题是项目名，返回回到第一级。
- 第一行固定是“在这个项目新建会话”。点击后展开或进入新建设置：
  - Agent：默认是 App 设置里的默认 Agent，可以改成电脑上可用的其他 Agent。电脑不支持的 Agent 不出现。
  - 权限模式：显示 App 设置里的默认权限模式，只读展示，附一句“可在设置里修改默认值”。这里不提供修改。
  - 不提供模型选择。
- 其后是这个项目的会话列表，最近修改的在前。每行显示会话名、Agent、状态、最近修改时间。
- 不可选的会话仍要写明原因（观察模式、离线等），规则同 v2.1。
- 项目里没有会话时，只显示新建入口和一句“这个项目还没有会话”。

### 3. 结果页上的目标入口

- 选中已有会话：显示“项目 · 会话名 · Agent”，同 v2.1。
- 选中新建会话：显示“项目 · 新建会话 · Agent”。
- 点击入口回到上次所在的那一级，并标出当前选中项。

### 4. 确认派发

- 目标块要让用户一眼分清是发到已有会话还是新建会话。
- 新建会话时，目标块显示项目、Agent、权限模式，并写明：“会在这个项目新建一个会话，第 1 项作为它的第一条消息。”
- 已有会话时，目标块增加一行权限模式，来自该会话当前的模式。
- N > 1 的多项提示原文不变，新建会话时同样显示。
- 主按钮文案：已有会话保持“进入会话并派发 N 项”；新建会话为“新建会话并派发 N 项”。

### 5. 新建会话的派发过程与异常

- 点击确认后进入聊天页，状态条先显示“正在新建会话…”，会话建好后再逐条发送。
- 新建失败（电脑拒绝、超时、Agent 不可用）：没有发送任何消息，所有待办保持草稿，返回备忘并说明原因。不自动重试，不换 Agent，不改发到别的会话。
- 会话建好之后，这条备忘的目标改为这个刚建好的会话。批次中途停止后，用户回到备忘再次派发剩余项时，发到的是同一个会话，不会再新建一个。结果页的目标入口此时显示这个会话的名字。
- 新建会话的第 1 项如果状态未知（待核对），规则同 v2.1：停止后续发送，不自动重发。

## 内容样例

电脑“我的 Mac”。项目与会话：

| 项目 | 会话 |
|---|---|
| Pairlet | 移动端构建排查（Claude，空闲）、文档整理（Claude，运行中）、依赖升级（Claude，观察模式，不可选） |
| docs-site | 站点迁移（Codex，空闲） |
| scratch | 暂无会话 |

默认 Agent 为 Claude，默认权限模式为“默认（每次询问）”。不要出现真实账号、个人目录或工作日志。

## 原型操作

原型必须能实际完成：

1. 结果页 → 选目标 → 从“最近会话”直接选中一个 → 回到结果页。
2. 选目标 → 进入项目 Pairlet → 选中“移动端构建排查”→ 确认 → 进入聊天派发。
3. 选目标 → 进入项目 scratch → 新建会话，把 Agent 改为另一个 → 确认页显示新建会话的说明 → 派发 → 聊天状态条显示“正在新建会话…”→ 逐条送达。
4. 新建会话失败的场景：返回备忘，三项都是草稿，有原因说明。
5. 新建会话后部分送达：返回备忘，目标入口显示新会话的名字，主按钮只统计草稿。

演示控制增加“新建会话结果：成功 / 失败”，仍放在手机框外。

## 视觉与验收

- 390 × 844 为主，补 320 宽和 200% 字号。两级页面在 320 宽 200% 字号下，项目名和会话名换行显示，不截断到看不出是哪一个。
- 触区不小于 48 dp。同行文本与图标、徽章的视觉中心一致。
- 画板增加一节“目标选择 v3”，包含：第一级、第二级、新建设置、两种确认页、新建中、新建失败各一帧，以及 320 / 200% proof。原有 v2.1 的画板保留；v2.1 里那张平铺的目标选择帧标注“已被 v3 取代”。
- 完成后实际打开画板自查，输出：改动摘要、已检查项、未验证项。
