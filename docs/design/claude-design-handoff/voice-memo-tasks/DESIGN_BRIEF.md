## 本轮目标与文件边界

在 cc-pocket Design System 2.0 项目内，为 Pairlet 手机 App 设计“语音备忘转任务”。这是新主题，不延续当前打开的 Recent Row Actions 或任何旧聊天任务。

只新建 Voice Memo to Tasks v2.dc.html 及必要的 VoiceMemoV2Phone.dc.html 组件；不修改任何现有项目文件。使用项目现有 Design System、Mobile UI 2.0、Settings Supporting Surfaces、Defaults + Voice + Results UI 2.1 的相关基础；聊天展示沿用 Chat Master/Chat Roles/Chat Rhythm 的当前方向。先读取所需 token 和组件，避免重造品牌、字体和颜色。最终产品名用 Pairlet，界面中文为主，保留英文项目/Agent 标识。

## 问题与已确定的产品语义

用户离开电脑时会一次想到几件事，需要完整口述，先核对摘要与待办，再明确选择会话派发。不要做成普通聊天语音输入框，也不要让录音结束自动启动执行。

链路：手机录音 → 加密上传电脑 → 电脑本地 Whisper 转写 → 已配置 Claude 整理 → 手机编辑/勾选 → 进入目标会话并逐条发送。摘要器与执行会话分离；摘要不调用工具。功能尚未实现，原型数据只作设计验证，不能把模拟进度称为实测。

## 需要设计的页面与交互

1. **设置与准备**：设置 → 通用 → 实验功能的“语音备忘转任务”开关，默认关闭。开启后手机会话列表的更多菜单出现“语音备忘”，桌面不显示。页面显示绑定电脑及“Claude · 使用电脑配置”，没有模型选择器。首次使用明确说明“录音加密传到电脑本地转写；转写文本交给配置的 Agent，可能发往其模型服务；任务由你确认后派发”。旧电脑版本、离线或转写未配置分别显示真实原因和下一步，不自动下载。
2. **极简备忘列表**：标题、时间、文字状态、打开和删除；空态与“新建备忘”。本地保存，删除不会撤回已经发到会话的任务。无搜索、分组、标记、云同步。本轮按完整可发布体验设计；实现演示检查点只用最近一条，不另做一套缩水 UI。
3. **录音**：真实音量的视觉表达、经过时长、3:00 上限、“结束并整理”和“放弃”。2:45 提示剩余 15 秒，到上限自动结束并说明。录音时返回可继续录音/结束整理/放弃。没有实时转写、暂停/续录或后台录音；权限拒绝与系统中断有清楚的恢复操作。
4. **处理**：上传到电脑 / 本地转写 / 整理待办三个阶段，用真实阶段文字、spinner、经过时间；没有百分比、ETA、模拟音频听写。取消处理、上传中断、空转写、转写失败、整理失败或电脑处理记录不可用等状态可切换。音频停止后已本地保存，失败可重试；未知处理记录须由用户重新处理，不自动消耗 Agent 额度。离开此页面不取消已提交作业，回到前台查询状态。
5. **结果编辑**：标题可改、摘要只读、待办逐项勾选/改字/删除及手动新增；转写原文和处理耗时折叠。默认勾选待办，但必须明确派发。无待办时允许手动添加，不凑项；JSON 失败显示原文和“未能整理成待办”，有可信摘要才显示。底部显示选中数量、目标会话入口与“进入会话并派发 N 项”；0 项或未选目标不可发。
6. **目标会话与确认**：显示项目、会话名、Agent 和状态；归档、观察、权限不足、离线或需接管终端的目标不可选。只在已绑定电脑选择。一次选择一个目标，用户可分批向其他目标发。所有 N > 1 的确认都提示：“后续任务会在当前任务进行中送达，可能被并入同一回合。需要分别处理时，请分到不同会话。”不要只在会话原本忙碌时显示。选中正文必须可核对。
7. **派发进入聊天**：点击后进入所选目标聊天，等待打开，再发送；不是留在备忘页后台派发。聊天内使用简洁状态条呈现逐项送达汇总，并有“返回备忘”。待办只允许草稿/发送中/已送达/待核对/失败五种状态，绝不画逐条“执行中/完成”。实际 Agent 回复在现有聊天区域显示。成功项不可重发，未知项先查看聊天核对。正常进入目标聊天不打断批次，随后离开聊天或退后台暂停剩余项。

**关键异常样例**：三项发送，第 1 项已送达，第 2 项接收状态未知，第 3 项未发送；停止继续投递，显示“1 项已送达 · 1 项待核对 · 1 项未发送”，返回备忘后仍保留这三种不同状态，不能一个“重试全部”重复执行第 1 项。

## 内容样例与原型操作

示例标题“出门想到的三件事”；摘要“整理了构建排查、文档补充和发布检查三件事，先核对内容，再选择会话处理。”待办：

- 检查 mobile build 失败的原因，先给出诊断和修复建议。
- 补充 README 中的本地启动步骤，保留现有配置示例。
- 检查发布前清单，只报告遗漏项，暂时不要发布。

使用虚构电脑“我的 Mac”、项目“Pairlet”、会话“移动端构建排查”。不要出现真实账号、个人目录、联系人或工作日志。示例耗时为 75 秒录音、1.2 秒上传、8.4 秒转写、4.7 秒整理、15.1 秒总处理；明确是原型样例，实际缺测用“未完整测得”而非 0。

原型必须能实际完成：开关 → 列表 → 新建/停止 → 处理 → 结果；取消勾选、编辑文本和增加一项；展开原文/耗时；选会话、看到多项提示、进入聊天、返回备忘；重置、切换失败/部分成功。演示场景控制、主题/宽度/字号按钮放在手机框外，不能混进产品 UI。不要请求真实麦克风或真实服务。

## 视觉与验收

以 390 × 844 和 402 × 874 为主，补 320 宽、200% 字号和深浅主题。长待办可增长、多行文字可读；底部按钮与滚动/键盘不冲突；主按钮长文案允许合理换行，不缩字塞满。沿用现有 48 dp 触区，最低 44 dp；同行文本和图标/徽章的视觉中心一致，交接注明 Compose tightCenter、Trim.None。

交付一个主文件：可操作手机原型 + 必要状态画板 + 320/200% proof + token/间距/状态交互表。不需要多方向竞稿或另造设计系统。优先把结果核对与“进入聊天派发”的路径做完整。

验收时不能只给文字结论，要实际打开新画板并检查。输出新文件名、设计摘要、已检查项、未验证项；不要把原型等同于真实录音/网络/Agent 已通过。代码实现、调度器、后台派发、模型选择和逐条执行状态均不在本轮 UI 范围。
