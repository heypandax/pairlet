Session Archive — put a session away, get it back in one step Archive is daemon truth: archive on the phone, the row is gone on the desktop too. It is not delete, not expiry, not “done”. The row leaves the regular list immediately; opening an archived session does not bring it back.
Two rules carry the whole design: put-away is a menu verb, take-back is a visible control. Archiving is deliberate, so it lives behind long-press / right-click. Unarchiving happens in a room you had to walk into on purpose, so it is a persistent trailing control on every row — never a hidden gesture.
Colour law unchanged: terracotta only on the take-back action and the active scope · green 70% = still running · muted mono for paths, counts, branches.

Verdict on feedback: a toast, but never an “Undo”. There is no undo stack, and there does not need to be — archive and unarchive are exact inverses, so the toast simply offers the opposite verb (here Archive; after archiving from the chat it reads Unarchive). It is honest about what happened, it names where the session went, and it costs engineering nothing. Same toast fires on the archive side, where it matters more: a row vanishing from a list you were reading needs a receipt. Toast is 4s, tap-to-dismiss, never blocks the composer.

Ruling on the conflict: keep the ⌘K scope, do not build a second panel. A separate browser is a whole surface, a search field and an empty state for a list you visit monthly — and it would fork “find a session” into two places, which is exactly what archive is meant to un-fork. The palette already is the desktop's find-anything room; ARCHIVED is a scope inside it, entered by the sidebar row or by ⌘K → arch.
What actually fixes discoverability is not the hover icon — it is the footer legend, which is always visible and names both verbs the moment the scope opens. So: the icon shows on hover and permanently on the selected row (keyboard users never touch a mouse and must still see it), the label Unarchive is spelled out on the selected row only — icon alone on hover — and the footer carries ⏎ / ⌘⏎ / ⎋ at all times. Scope is a terracotta tag in the query field, so you always know which list you are typing into; ⎋ leaves the scope before it closes the panel.

Rulings on the three open questions

1 · mobile take-back: trailing icon / long-press / swipe?
Trailing icon. Persistent, 44dp, one tap, no confirm. The archive screen exists for exactly one verb — hiding it behind a gesture makes the room pointless. Swipe stays unimplemented rather than half-implemented.
2 · desktop second action: hover icon vs separate panel?
Keep the ⌘K scope. A separate panel duplicates search, empty state and navigation for a monthly-visit list. Discoverability is fixed by the always-on footer legend (⏎ / ⌘⏎) plus the icon pinned to the selected row, not by hover alone.
3 · ✕ vs Archive — how does each mean itself?
Different weight, different place, different words. ✕ is 22px, hover-only, on the row, worded Remove from recents — local, forgetful, self-healing. Archive is a menu verb with a box glyph and a shortcut, worded Archive session, captioned hides on all devices. They sit adjacent in the context menu so the pair is read once and never confused again.
4 · feedback for a vanishing (possibly running) row?
Toast, no undo stack. The toast offers the inverse verb, not an undo — same call, no engineering. It names the destination, and a running session's toast says still running, because a green dot disappearing is the one moment a user fears they killed something. Desktop shows no toast: the sidebar count bumping is receipt enough on a screen where the whole list is visible.
out of scope, on purpose
No delete, no expiry, no bulk select, no auto-archive suggestion, no change to the existing list or group layout. Archived sessions are excluded from the default ⌘K scope and from the sidebar — they only appear when you ask for them by name.
