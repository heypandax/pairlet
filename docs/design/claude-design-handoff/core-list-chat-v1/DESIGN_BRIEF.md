# 核心列表与会话体验 · 设计 brief

日期：2026-09-22（本机时区）。状态：已投递并完成设计 v1；结果与实际验证范围见 [README](README.md)。范围：设计＋功能方案，不含产品代码实施。

## 输入与观察

用户提供约 23 秒的手机录屏：项目页滚动、打开已有会话、滚动阅读工具与回复。约第 4 秒进入会话、约第 11 秒多出现正文，中间约 7 秒只有头部和输入区。此为单次录屏观察，不代表统计性能或已定位根因。

现有深色、陶土色强调、克制卡片方向保持。主要改进：继续任务的入口更清晰；加载有反馈；正文成为阅读主体；技术详情可查但不占据默认视图；头部、输入区及额度条语义更清楚。

## 基线与约束

- 项目：cc-pocket Design System 2.0；沿用项目语义 token、字体和图标。
- Chat Master v2 为框架参考，但 Chat Roles v1 已局部替代用户消息样式；保留中性封闭用户容器、明确“你”标签和 Agent 文档流。
- 当前源码优先：单纯运行不再单独占一条顶部状态栏；审批／提问／真实失败才出现需处理状态。不能照旧稿重复运行提示。
- 当前额度条数字使用已用百分比；Claude 保持 5h＋7d，Codex 保持账号级 7d，不增造模型额度。
- 已有执行过程折叠，建议在此基础上调整默认摘要与详情层级；连续成功普通工具／已结束思考可折叠，失败、运行和未知结果保持独立可见并中断分组，不跨正文拼组。不引入额外模型调用来生成摘要，不隐藏审批／提问，也不把单次工具失败等同整个任务失败。
- 会话已有历史完成与布局观测。观测不直接驱动重发、清空消息或 Agent 生命周期；缓存与性能优化列为待评估能力。

## 设计产物

在现有项目新建 `Core List Chat v1.dc.html`，必要辅助文件使用 `CoreListChatV1` 前缀。其他项目文件不修改。

中文移动端，402×874 主画板，保留现有设计系统。提供一条推荐方向，不生成多套相互竞争的方案：

1. 项目／会话入口：清晰区分“继续会话”和项目，使用两行标题、独立状态，项目内“新建会话”与全局新建入口语义明确。
2. 会话：收敛头部常驻信息，机器、模式、项目路径可展开；用户与 Agent 区分保持；正文优先；输入区保持可达。
3. 加载：加载历史、加载较慢但原因未知、明确加载失败、确认空会话；不能用空白或假进度百分比代替状态。
4. 执行详情：成功过程折叠摘要、展开工具、独立失败项；原始命令可展开／复制，摘要用已有工具名与状态，不能编造业务成功结论。
5. 需要处理：审批／提问可见且沿用既有决策入口，不将其收进过程折叠。
6. 额度：常驻紧凑入口明确“已用”，点击明细；未知不是 0%，沿用无数据时不展示条的现状。

交互至少包括从列表进入会话、返回、上下文展开、执行过程展开／收起、额度明细、加载状态切换及“回到最新”。可用画板外状态控件进行演示，产品内不出现调试开关。

验收覆盖：深色主路径、浅色对应页面、320pt 长标题／长命令压力、放大字号（避免缩字解决溢出）、关键状态。保持触控区域至少 48pt，可见图标可以更小；正文默认 14sp 基线，放大时内容与操作仍可达。不新增底部 tab、不重做品牌、不扩展到桌面全套。
