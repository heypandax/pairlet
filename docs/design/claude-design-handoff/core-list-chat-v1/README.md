## 设计基线与采用范围

本轮是待评审的核心界面优化提案，不自动替代已实施的设计。沿用项目设计系统、[Chat Roles v1](../chat-roles-v1/README.md) 的中性用户容器及当前源码中的聊天状态和折叠边界。

## 推荐方向

- **继续会话优先**：需关注的会话使用卡片，最近会话使用轻量列表，项目目录置后；项目内新建与全局新任务分开命名。
- **正文优先**：成功工具的连续过程收成计数行；失败、运行及待处理工具独立展示。Agent 回复保持文档流，用户消息保留中性容器。
- **头部收敛**：常驻标题和一行项目／机器上下文，其余资料展开查看；短屏限制展开区高度以保留输入区。
- **等待有解释**：加载、较慢、明确失败、未确认、确认空历史分开；未知原因不包装成网络诊断。
- **关键能力保持可达**：双层输入区、独立审批面、问题卡、额度明细和回到最新。

## 验证与归档

生成模型：提交时页面显示 Opus 5.5 Medium；使用用户的 Claude Design 额度，未取得精确消耗量。

初稿已实际查看并完成集中修正：失败工具独立展示；补回双层输入区；审批／提问提示只路由到原决策面；打开会话保持标题／Agent／项目身份；增加未知历史终态并使用真正的长文本压力数据。生成器自检还修正了独立工具行未渲染的问题，随后已在主画板确认失败工具出现。

| 实际检查 | 结果与范围 |
|---|---|
| 列表→会话→返回 | 点击 Demo Web 的 Codex 任务，标题、Agent、项目对应；再打开 Demo App 的 Claude 历史，身份正确 |
| 上下文 | 可展开；机器、Agent、模式、项目和路径可见；最后修订后实看 320pt 画面，完整会话标题可读，输入区仍可达 |
| 输入状态 | 运行中空输入显示停止；输入草稿后增加排队发送；空闲有麦克风，附件／模型／上下文入口存在 |
| 执行详情 | 成功过程可展开到各工具，再展开到预览和复制入口；独立失败行已在深浅主画板确认 |
| 历史状态 | 手动切换加载、较慢、明确失败、未确认和空历史；未确认保留已有正文，空历史有明确文案 |
| 审批与问题 | 查看请求打开独立权限面；问题选项位于消息流，顶部提示路由到该位置 |
| 阅读跳转 | 定位较早消息后出现回到最新；点击后跳回末尾并隐藏入口 |
| 额度 | 明细显示已用，Claude 两窗口＋Codex 周窗口；无数据时条被移除 |
| 视觉检查 | 查看深浅对照、320pt 长数据及 130% 字号画面；不是全量自动布局测量，也不是设备可访问性认证 |
