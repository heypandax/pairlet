# 飞书机器人单聊底部菜单

给飞书机器人配一排常驻快捷入口：在单聊窗口底部点一下，等于替你发出一条命令，省掉手打。

配置全部在飞书开放平台的开发者后台完成，cc-pocket 这边**一行都不用改**：菜单发出的就是你平时手打的那几条命令（前提是 daemon 已支持单聊，见文末「两条边界」）。

## 为什么是「发送文字消息」型菜单

飞书的机器人菜单**没有 OpenAPI**，只能在开发者后台手工配置，所以这里给的是一份可照抄的标准约定，而不是脚本。

菜单动作一律选「发送文字消息」：点菜单等于用户自己发了一条命令文本，走 cc-pocket 已有的单聊命令链路——daemon 不用加任何 handler，也不会因为 daemon 升级而失效。（飞书另有「推送事件」型菜单，需要额外订阅事件并在 daemon 里加处理逻辑，收益只是聊天里不留一条命令消息，暂不采用。）

## 标准菜单：只配一项

⚠️ 关键事实（2026-08-15 真机后台实测）：「发送文字消息」型菜单**没有独立的“发送内容”字段——菜单名称本身就是被发送的文本**（后台原文：The menu text will be sent as messages）。所以菜单名称必须以命令开头才能被识别；命令后可以跟一段中文说明，daemon 解析时把首个空格后的部分当作参数忽略掉。

| 菜单名称（即发送内容，逐字照抄） | 动作类型 | 作用 |
| --- | --- | --- |
| `/new 新会话` | 发送文字消息 | 清空当前上下文，下一条消息重新选项目 |

只配一项是真机验证后的定稿（2026-08-15）：单聊是机主场景——自动路由让 `/projects` 冗余，`/trust-status` 对机主是废信息；多配菜单还会挤占输入框。动态操作面（选项目、绑定等）走 `/menu` 交互卡片，不靠静态菜单。

**形态建议**：展示形态选「可收起」、**默认视图选「输入框」**——菜单收在切换图标后面，不干扰打字。

**名称必须以 `/命令` 开头**：写成「🆕 新会话」这类不带命令的名称，点按后发出的就是这几个字，会被当成普通提示词而不是命令。命令拼写要逐字一致（`/new-session` 这类变体不会被识别）；命令后的中文说明可自定，但只能用空格隔开、不能插在命令前面。

## 配置步骤

1. 打开[飞书开放平台](https://open.feishu.cn)，进入「开发者后台」→「我的应用」，选中 cc-pocket 在用的那个自建应用。
2. 进入应用能力里的**机器人**配置页，找到**机器人菜单**一栏（英文后台叫 Custom bot menu；入口名称与层级可能随后台改版微调，认准机器人配置页内带「菜单」二字的那一项即可），菜单状态切到「开启」。
3. 按上表添加菜单项：菜单名称逐字填入上表第一列 → 动作类型选「发送文字消息」。展示形态选「可收起」、默认视图选「输入框」。
4. 保存。
5. **发布应用版本**：进入「版本管理与发布」→「创建版本」→ 填版本号与更新说明 → 申请发布。菜单只有在新版本发布通过后才生效，光保存不发版是不会出现的。

## 生效与验证

- 发布通过后约 **5 分钟**生效，期间客户端可能仍显示旧菜单。
- 没看到菜单：先确认版本已发布通过，再关掉并重新打开与机器人的单聊窗口（客户端有缓存），必要时重启飞书客户端。
- 验证：在单聊里点「/new 新会话」，机器人应当回复「已开新会话」。

## 两条边界

- **菜单只出现在单聊。** 飞书的机器人菜单只在单聊窗口底部展示，群聊里没有这一排。群里继续 `@机器人 /projects` 这样用，不受影响。
- **单聊免 @ 需要较新的 daemon。** 在单聊里直接发命令（不用 @）是 v1.7.7 之后加入的统一收件箱能力；更早的 daemon 请在群里 `@机器人` 加命令使用。

## 零配置替代：`/menu` 卡片

不想动开发者后台的话，直接在聊天里发 `/menu`：机器人回一张交互卡片，含「新会话／项目列表／状态」三个按钮——低频操作走这里，不必落进常驻菜单。点一下等价于你自己手打那条命令——同样的身份、同样的绑定与信任规则，卡片本身不附带任何额外权限。

| | 底部菜单 | `/menu` 卡片 |
| --- | --- | --- |
| 配置 | 开发者后台手工配 + 发版 | 无，装好即有 |
| 位置 | 单聊窗口底部常驻 | 聊天流里的一条消息，随发随用 |
| 群聊 | 没有 | 有（`@机器人 /menu`） |

两条路线可以并存，按钮集合刻意保持一致。`/menu` 需要 v1.7.7 之后的 daemon；更早的版本请走上面的底部菜单。daemon 重启后，历史消息里的旧卡片会失效（点了只提示重新发 `/menu`），这是有意为之：聊天记录不该变成一堆长期可用的遥控器。

## 想加更多菜单

同样的做法可以配任何单聊命令，名称照「`/命令 中文说明`」格式写即可。但先想清楚是否真的高频到值得常驻——低频操作发 `/menu` 用卡片就够；完整命令表在聊天里发 `/help` 查看。
