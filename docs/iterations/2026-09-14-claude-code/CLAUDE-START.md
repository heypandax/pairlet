# Claude Code：Opus 主控与并行执行入口

本文件可直接交给 Claude Code。仓库内真实规则由根目录 [CLAUDE.md](../../../CLAUDE.md) 导入 [AGENTS.md](../../../AGENTS.md)；本交接的执行方式优先于历史“Codex 调度 Opus”的说明。无需读取 Codex 会话或本机私有 skill。

将下面的指令放入一个 **Opus 5 主会话**。该会话持续负责调度与集成，其他 Claude Code 子任务并行实施并向它同步。本文定义分工，不会自动切换当前会话的模型；以实际环境提供的模型信息为准。

## 首批并发分工与同步

| 执行者 | 并行任务与所有权 | 向主控交付 |
|---|---|---|
| Opus 主控 | 任务板、接口约定、共享文件接线、集成和组合回归调度；分派后持续处理依赖与评审 | 一份完整候选 diff 和逐项状态 |
| 实现 A | #381-A：ReleaseClient 下载进度与 daemon CLI；不进入 UI 文件域 | 进度实现、兼容与取消／失败行为证据 |
| 实现 B | #380-MVP：展示投影、稳定标识策略、独立折叠组件与相关用例；不写已归主控的入口文件 | 组件、投影映射及两端接线说明 |
| 实现 C | #320-A：未知状态展示、独立说明组件及文案；不写已归主控的入口文件 | 状态分支、组件及两端接线说明 |
| 独立评审上下文 | 对已集成的单项 diff 开始评审；与仍在实现的其他项并行 | 具体发现、作者返修后的复核结论 |

子任务开工前，主控把上述模块边界细化成实际文件路径，并约定组件接口。建议新增组件的名字不是既有 API，按源码确定；接口未确定时可以先并行调查和写独立逻辑。#380、#320 的共享聊天入口按 #380 → #320 接线，独立组件仍同时开发。

- **工作区与交付**：每个子任务从同一已核验源码基线开始。若交接文档尚未提交，主控将本目录复制到子工作区或明确提供可读路径，不能假定新 worktree 已带上它们。记录实际工作区和负责路径。交付未提交 diff／新增文件清单，由主控检查后应用到集成工作区；本指令不要求子任务 commit，也不暗中扩大提交授权。
- **同步记录**：主控单独维护 `_local/claude-issue-batch/task-board.md`，状态使用“待开始／实现中／待集成／评审中／返修中／候选可审／阻塞”。每条记录包括最新依赖、验证结果和下一责任人；子任务只回报自己的摘要，不同时改任务板或本目录的状态文档。原始长日志留在各自工作区，不反复灌入主控上下文。
- **范围变化**：子任务需要新文件域、接口变化或他人的改动时，先回报主控；主控交接所有权后再继续。允许重新拆分任务，但不能借并行工作自动开启下一批。主控向用户汇报已集成项、当前阻塞和下一步，不只报“子任务运行中”。
- **构建资源**：不同子任务可做互不干扰的定向检查；同一工作区的 Gradle／Xcode 构建串行。主控协调宿主机资源，组合回归只在集成工作区安排一次；只有新增改动、失败或未解决风险才扩大或重跑。
- **评审与整合**：评审针对包含实际接线的完整切片，附基线和文件摘要／哈希；后续整合改动涉及已评审行为时补差异复核。主控的集成修正也计入作者范围，最后检查整批组合行为，不能用各工作区单测通过代替集成验证。

## 执行契约

1. **基线**：本方案核验自 `d7f06c17b8f1154adf55926d46fca3b0d3cd4b81`。开工前读取当前 main；有后续提交就判断影响，不回退到旧快照。`gh repo view --json nameWithOwner,defaultBranchRef` 可确认仓库，Issue 原文通过 `gh issue view N --repo heypandax/pairlet --json title,body,comments,state,assignees` 读取。
2. **范围**：方案里的类名／帧名标“建议新增”时不是现有 API。沿实际工程调整文件落位可以自主处理；产品范围、信任关系或兼容策略发生实质变化时先更新方案、说明原因。
3. **文件所有权**：首批按上表并发实施、由主控整合共享文件。后续获准启动时，#363 修改新建面板；#360 会碰 Repository／桌面侧栏／协议，排在前三项之后；#367 最后进入协议及权限域。后续批次也由主控先分文件域和依赖，再派子任务。
4. **审查**：评审输入是实际 diff、基线、对应方案、失败→通过的证据和未验收项。评审者给具体文件／行为／优先级；作者修复后由评审者复核。不要要求专用 Codex agent 名称存在。
5. **记录**：运行日志、屏幕录像、设备标识、原始回复放仓库外或 `_local/`。仓库文档仅写脱敏摘要、代码锚点和可复现命令；不把原始会话或个人构建配置提交。
6. **完成口径**：代码实现、测试通过、独立评审、设备验收、提交、发布分别记录。Issue open 可能只是待交付；不要把“已改”自动换成“可关单”。

## 构建与验证

先做与改动直接相关的测试，不重复刷全仓结果。需要组合回归时使用仓库入口：

```bash

JAVA_HOME=/opt/homebrew/opt/openjdk@17 ./gradlew :mobile:composeApp:compileKotlinDesktop
```

以上路径是本机 macOS 提示；其他主机使用其真实 JDK／SDK。合并前使用无参数 `bash scripts/check-all.sh`；缓存命中与实际执行分别记录。UI 需要观察真实界面；iOS 共享代码改动至少编译受影响 target，真机／多任务／键盘验收按专文，不用 JVM Compose 用例代替。

**Linux 不在本期验证计划。** 不启动 Linux 容器、Docker、额外 Linux 打包或多架构设备；现有公共 JVM 回归可以在当前 macOS 跑，不能将其称为 Linux 验收。

## daemon 与设备操作

普通单测不需要启动第二个 daemon。禁止 `:daemon:run`、直接运行 installDist 可执行文件、手写 nohup 实例。得到设备更新授权后，普通终端只用 `scripts/update-local-daemon.sh`；daemon 驱动的会话用 `scripts/update-local-daemon-detached.sh`，daemon 放最后。脚本若报告其他活会话，按 AGENTS.md 报清单并取得中断授权，不能自行 FORCE。

不要将为旧批次给出的提交／设备授权理解为这次新代码也已获授权。普通实现与必要验证保持连续推进，真正的设备中断、发布或权限扩大由用户决定。
