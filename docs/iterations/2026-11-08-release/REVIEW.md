# 2.6.2 发布候选审核

## 范围与基线

候选工作区基于远端 `main` 的 `40de8b56`（2.6.1 发布渠道同步），分支 `codex/release-2.6.2-review`。原迁移分支停在 `843a844c`，与已发布主线有 109 个文件的差异；本轮没有从旧分支整体覆盖主线。

纳入 #417 Codex 大转录观察、#415 后台服务端口参数，以及 cn 入口迁移的剩余 HTTP/遥测/Harmony 路径。已发布的默认 cn 入口、客户端原始配对身份、Codex 初次观察发送完整窗口和先宣布会话后回填元数据的行为全部保留。

维护者随后要求纳入当前修改：本轮 fir 候选已补入原工作区的 Markdown 代码块换行、窗口边界恢复改动。本次正式提交同时纳入美国推送出口模板和香港暂停/恢复记录，不重部署服务。

## 审核发现与处理

| 发现 | 处理 |
| --- | --- |
| 旧迁移分支缺少 2.6.1 已发布修复，不能直接发版 | 在最新主线创建独立工作区，逐文件迁入，保留主线的观察会话顺序及无跨文件身份的旧游标保护。 |
| 初版增量读取遇到临时 IO 错误会退出整个观察循环 | 捕获 IO 失败，返回不擦除已有历史的空 delta，不确认新游标；下一 tick 即使 mtime/size 不变也重试，从完整窗口重建。新增失败恢复测试。 |
| `service-install` 可能接受越界端口或两个监听器使用同一端口 | 在生成服务之前给出 CLI 错误，新增无效值/冲突值回归。 |
| 旧分支的迁移规则没有覆盖主线已经支持的官方 `:443` 写法 | 复用主线 `transport` 规则，HTTP 与 Harmony 同步覆盖；自托管端口、路径、查询参数保持原样。 |
| Pairing.kt 是兼容性冻结文件 | 核对仅请求 URL 解析改变，持久化配对结构、密钥、链接和 wire 未变；更新该文件指纹及审阅依据，其余冻结文件不变。 |

- #417 首次打开和主动翻旧页仍扫描文件；周期性观察更新改为追加读取。没有取得反馈者原始 Windows 269 MB 文件的实机验收。

- #406、#409 等待反馈者复测；#407 仍缺现场模型目录，#408 仍不支持 Dot 云端任务。
- 初版候选未改 UI；随后 fir 候选补入代码块换行和窗口恢复，未运行真机 UI 自动化或生成回放。连接逻辑单测和平台编译不代替设备验收。
- 提交准备、签名安装包构建、商店提交和对外发布分别记录。此文档不表示已推送 main、打 tag、发布 Release 或重启本机 daemon。
