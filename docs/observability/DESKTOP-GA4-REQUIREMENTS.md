# 桌面端 GA4 正式采集需求

日期：2026-09-11。状态：**后续开发需求，尚未实现；仅保留本地，不纳入本次提交**。供后续实现使用，不要求本轮开发、部署或补充验收。

## 要解决的问题

正式桌面用户的首次使用、核心操作结果、功能采用和留存，需要进入现有 GA4 产品分析视图。目前桌面端通过 Measurement Protocol（MP）直连 GA4，仅在本机配置 measurement ID 和 API secret 时开启；普通官方包不携带这份私有配置，因此本机测试有数据不能证明正式桌面用户已被覆盖。

MP 的 `api_secret` 是私密上报凭据，不能随客户端分发；泄露后可被用于伪造事件、污染分析数据。将它放入 GitHub Secrets 后再写进安装包，同样会泄露。这里的“私钥”应准确称为 **GA4 MP API secret**，不是非对称加密私钥，也不是可公开的 Sentry DSN。依据：[Google MP 发送事件说明](https://developers.google.com/analytics/devguides/collection/protocol/ga4/sending-events)。

本需求只补桌面 GA4 的正式入口。现有桌面 Sentry 错误/日志、手机 Firebase Analytics 与 Crashlytics 保持各自职责。

## 产品目标与范围

| 目标 | 应回答的问题 / 口径 |
|---|---|
| 首次使用与首次价值 | 桌面用户在哪一步退出，是否完成首次有效使用；包含尚未配对时的启动与引导 |
| 核心操作完成 | 打开会话、发送请求、完成回复和断线恢复，分别有多少成功、失败、超时和未知结果 |
| 功能采用与复用 | 用户是否看到并实际使用功能；沿用 exposed/used 与现有 value 事件，避免只统计点击 |
| 版本与留存 | 按版本、环境、使用模式对比，等待成熟数据再计算 D1/D7；不把匿名安装数解释为跨设备去重人数 |

沿用 [事件目录](EVENT-CATALOG.md) 与 [产品分析口径](PRODUCT-INSIGHTS.md)，本批不另建一套事件名称、不更换统计 SDK、不引入付费数据仓库。daemon/relay 的运维事件继续走诊断体系，不能记成桌面用户行为。

## 建议架构

```text
桌面 Telemetry → 独立 HTTPS 分析入口 → 服务端验证与构造 MP 请求 → GA4
                         ↑
                 服务端运行配置中的 API secret
```

建议复用现有服务器基础设施，但分析入口必须具有独立路由、访问控制、资源限额和关闭开关。不能通过监听或解密 relay 业务流量采集行为，不改 E2E 协议，不读取会话正文。进程部署方式在实现前确定；即使共用宿主，也必须保证分析请求耗尽额度或上游故障不会拖垮 relay。

桌面只配置公开入口地址。服务端自行选定 GA4 数据流和凭据，不接受客户端指定上游 URL、measurement ID 或 API secret，不能做任意 JSON 透传代理。

## 必须满足的行为

### 事件与分析连续性

- 保留现有事件触发位置、成功/失败语义、`coverage` 和数值耗时。事件及参数白名单以 EVENT-CATALOG 为准，服务端再校验名称、类型、枚举、长度和数值范围。
- 新事件继续使用字符串 `analytics_schema=v1`，保留 `app_platform=desktop`、版本、环境、internal traffic、usage mode 等已定义字段；历史查询兼容旧 schema。服务端入口版本单独管理，不能用更改产品事件含义来处理传输升级。
- 沿用本地持久化的匿名安装种子、GA4 client ID 转换及首次价值标记，避免升级后产生一批假新用户。清除本地数据或重装仍可能形成新身份，不承诺跨设备识别同一人。
- 延续 GA4 会话关联所需字段。现有固定 `engagement_time_msec=100` 不能当成真实活跃时长；若本批不实现真实前台计时，报表明确不使用它推导时长结论。
- production、staging、内部测试及 demo 必须可区分；发布配置决定入口，服务端凭据决定可写数据流。客户端自报平台/环境是统计字段，不能充当鉴权凭据。正式数据不得混入开发探针。

### 采集开关与故障体验

- 继续使用 App 现有持久化采集开关和默认值。关闭时不得注册分析身份或发送分析事件；清空待发送队列并取消在途请求，重新开启不重放关闭前的队列。
- 已到达服务器或 GA4 的事件无法由客户端取消追回；设置说明与验收不能承诺追溯删除。
- 上传异步执行，不阻塞启动、配对、打开会话、发送消息或退出。离线、429、服务端故障、GA4 超时均不向用户弹业务错误。
- MVP 保留有界队列和允许丢失的语义，不要求磁盘积压、完整重放或“恰好一次”。客户端与服务端的超时、队列大小和并发上限必须明确；如增加重试，先定义重复事件及退避策略，不能隐式放大流量。
- 服务端提供独立关闭入口及配额控制；关闭或回滚后 App 核心功能和 Sentry 诊断继续正常工作。禁止自动退回携带共享 secret 的客户端直连。

### 接入控制与隐私

- 实现前确定接入控制方案，不能将一个打包进 App 的共享 token 当成秘密。建议评估匿名安装注册、短期且只可写入分析的令牌，并结合每安装、网络来源和全局限额；安装 ID 可重置，不能将此方案声称为真实用户认证或完全防伪。
- 首次启动及配对前行为也在范围内。若采用已有登录/配对认证，必须说明未配对用户如何上报；不能静默丢掉引导漏斗后仍宣称覆盖全部桌面安装。
- 不复用 E2E 私钥、配对凭据、Sentry 管理 token 或 GA4 secret 作为桌面上报凭据。认证、限流和资源隔离方案需要在编码前形成可评审的契约。
- 禁止传入 prompt、对话/日志/栈正文、项目/文件/会话名称、路径、仓库 URL、账号标识、业务会话 ID 或业务诊断 trace ID；不增加设备指纹。只接受目录中明确允许的产品字段及传输必需的匿名标识。
- 服务端默认不持久化原始事件体。入口代理及应用日志不记录请求体、认证头、完整 IP 或含 secret 的 GA4 URL；网络地址只在有界的接入控制中按需使用，并明确保存期限。
- 无效请求明确拒绝并限制大小/频率；不能靠客户端白名单保护公开入口。诊断仅保留安全计数、状态分类和延迟，失败上报不得递归制造 Sentry 事件风暴。

## GitHub CI 与运行配置

| 配置 | 放置位置 | 能否进入桌面安装包 |
|---|---|---|
| HTTPS 分析入口地址、公开环境标记 | 构建 Variables 或公开构建配置，正式/预览分开 | 可以 |
| MP API secret | 服务端运行环境的 Secret；需要 CI 部署时只注入受限部署步骤 | 不可以 |
| 服务端数据流映射、配额、开关 | 服务端运行配置，按环境隔离 | 无需进入 |
| Sentry DSN / 符号上传 token | 沿用 [发布配置](RELEASE.md) 的 Variables / Secrets 分工 | DSN 可以；上传 token 不可以 |

具体变量名与入口域名在实现时确定，本文件不表示这些配置已创建。MP secret 支持服务端轮换，无需更新客户端。不得把 Secret 写入仓库、构建日志、缓存或可下载 artifact。

保留 `scripts/observability-release-config.py` 拒绝 `ga4.properties` 的门禁，并扩展为检查新的桌面配置；所有官方桌面产物都必须只含公开入口。当前开发机的直连配置保持私有测试用途，实现时显式处理其优先级，避免官方包被旧配置绕回直连路径。

## 验收边界

以下由后续实现任务执行，不是当前合并的新增前置条件。

- 一个代表性真实桌面包覆盖未配对启动/引导、配对后会话成功、一次失败或恢复、首次价值和一个功能采用事件；与现有产品字段对应。若跨平台传输实现不同，再补相应平台，不重跑全量业务矩阵。
- 抽样检查关闭采集、在途取消、重新开启不重放、离线/超时/429，以及升级前后匿名身份连续；核心操作不受分析故障影响。
- 服务端验证未知字段/事件、超大请求、错误接入凭据和超额请求；检查客户端包与服务端日志中没有 secret、请求正文或不允许字段。
- 分别记录“入口收到”“上游请求成功”“GA4 已处理入报表”。MP 返回 2xx 不保证数据有效或已处理；验证端点也不会将测试事件写入报表。依据：[MP 响应说明](https://developers.google.com/analytics/devguides/collection/protocol/ga4/reference)、[验证事件说明](https://developers.google.com/analytics/devguides/collection/protocol/ga4/validating-events)。
- GA4 DebugView/Realtime 用于排查链路，最终用普通聚合核对 `desktop`、版本、schema、结果/coverage 及环境切片，说明可能的丢失和处理延迟。D1/D7 等真实数据成熟后再观察，不用测试回放代替留存。

当前手机/iOS 验收、Sentry 接入和历史超时的收尾边界仍以 [CLOSEOUT](../archive/observability-2026-09/CLOSEOUT.md) 为准，不因本需求重新开启。
