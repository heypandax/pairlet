Pairlet (formerly CC Pocket and CC Pairlet) is the same app with the same bundle ID and pairing data; no separate installation or re-pairing is needed. The App Store names are "Pairlet: Coding Agents" (English) and "Pairlet" (Chinese). It controls the open-source Pairlet daemon on the user's own computer: https://github.com/heypandax/pairlet. The command is pairlet; cc-pocket-daemon remains supported.

REVIEW WITHOUT A COMPUTER: read "Before you start" and tap "Agree and continue". On "Connect your computer", tap "Explore the demo instead" ("No computer needed"). "Pair a computer" also has this button. Projects, chat, tool approvals and usage screens run on built-in sample data, without an account, pairing, network dependency or AI calls.

CODING SESSIONS: users separately install and authenticate command-line coding tools on their own computer. Those tools contact their providers with the user's credentials. Prompts and session content between the paired app and daemon are end-to-end encrypted; our relay forwards ciphertext. Default voice dictation uses Apple's Speech framework. The optional alternative sends audio end-to-end encrypted to the user's computer for offline whisper.cpp transcription.

VOICE MEMO TO TASKS: the experimental Settings > General switch is off by default. Memo audio goes end-to-end encrypted to the paired computer for local whisper.cpp transcription. A user-installed and authenticated CLI (Claude Code or Codex) contacts its provider using the user's account to organise the transcript into to-dos. Without that tool, the transcript is preserved. Each to-do is sent to a coding session only after review and confirmation. A consent sheet explains this flow before the first recording. This requires a paired computer and is unavailable in Demo mode.

VOICE CORRECTION IN 2.6: Settings > General > Voice input > After dictation defaults to "Put in the composer". Opting into "Correct and send" first shows a separate disclosure: the transcript and project context (name, branch and file names) go to the configured agent CLI on the paired computer, which contacts its model provider using the user's own account. This is not on-device-only processing. Changes are checked before sending; uncertain changes or failures leave text in the composer for review. Users can disable correction at any time. A compatible computer-side agent is required; Demo mode does not make live AI calls.

OPTIONAL HELP: the Help screen opens our website's AI support, a separate HTTPS service outside the encrypted coding-session channel. Submitted questions are processed by the project-operated support server and its configured model provider. Analytics, crash reporting and push notifications also use separate services, explained at https://pairlet.org/privacy.html.

DIAGNOSTICS: Settings has "Share usage and diagnostics" and a copy-latest-diagnostic-ID button when an ID is available. Firebase provides usage analytics and crash reports. Sentry receives structured diagnostic errors, logs and timing information, excluding prompts, conversation text, file paths/contents, agent output and pairing credentials. These use separate HTTPS requests, outside the encrypted relay channel. The app toggle controls this app; the daemon has its own setting.

NEW IN 2.6.1: usage controls show quota reset cards already available in the user's existing Codex account on their computer. Pairlet does not sell cards. Redemption requires explicit confirmation and is handled by the computer-side CLI. Settings can request an update of a compatible paired computer. DeepSeek Harness retains the chosen model's provider and keeps the message unsent if that model cannot be applied.

No Pairlet account or login is required. Coding-session transport uses standard TLS + Noise/X25519/AES-GCM; ITSAppUsesNonExemptEncryption is false.
