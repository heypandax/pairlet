Pairlet (formerly CC Pocket) was shown as "CC Pairlet" on the App Store and on the device during a transition period that started with version 2.0.0. This version shortens that name to "Pairlet". It is the same existing app, with the same bundle ID and pairing data; users do not need to install a separate app or pair again. It is a companion for the open-source Pairlet daemon that runs on the user's own computer (https://github.com/heypandax/pairlet). Pairing therefore requires a desktop machine. The new desktop command is pairlet; the legacy cc-pocket-daemon command remains supported.

TO REVIEW WITHOUT A COMPUTER: on the pairing screen, tap "Try Demo - no computer needed". The entire UI (project list, chat, tool approvals, usage dashboard) then runs on built-in sample data - no account, no pairing, no network dependency, no AI calls.

CODING SESSIONS: the app is a remote control for command-line coding tools that the user has separately installed and authenticated on their own computer. The coding tool on that computer communicates with its provider using the user's own credentials. Prompts and session content transported between the paired App and daemon are end-to-end encrypted; our relay only forwards ciphertext. Voice dictation uses Apple's system Speech framework by default; the optional alternative sends audio end-to-end encrypted to the user's own computer for offline transcription by locally installed whisper.cpp.

VOICE MEMO TO TASKS (2.2, experimental, off by default): Settings > General has a "Voice memo to tasks" switch. When enabled, the user records a short memo; the audio is sent end-to-end encrypted to the user's own paired computer, transcribed there by locally installed whisper.cpp, and the transcript is organised into to-do items by the command-line coding tool (Claude Code or Codex) that the user has installed and authenticated on that computer, which contacts its provider with the user's own credentials. Without such a tool the transcript is kept as is. Nothing is executed automatically: each to-do is sent to a coding session only after the user reviews and confirms it. Before the first recording the app shows a consent sheet describing this data flow. The feature is not available in Demo mode and needs a paired computer.

OPTIONAL HELP: the Help screen can open our website's AI customer support. This is a separate HTTPS service, outside the encrypted coding-session channel. Questions submitted there are processed by the project-operated support server and its configured model provider. App analytics, crash reporting, and push notifications also use separate services, as described in the privacy policy: https://pairlet.org/privacy.html

DIAGNOSTICS IN 2.0: Settings includes "Share usage and diagnostics" and a button to copy the latest diagnostic ID when one is available. Firebase continues to provide usage analytics and crash reports; Sentry receives structured diagnostic errors, logs and timing information. Sentry diagnostics exclude prompts, conversation text, file paths and contents, agent output and pairing credentials. These are separate HTTPS requests, not part of the encrypted coding-session relay channel. The app setting controls this app only; the computer daemon has a separate diagnostic setting.

No Pairlet account or login is required. Coding-session communication with the user's own computer uses standard encryption algorithms only: TLS + Noise/X25519/AES-GCM (ITSAppUsesNonExemptEncryption is false).
